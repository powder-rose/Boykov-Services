# Boykov Services · Статистика сайтов

Патч добавляет отдельный раздел статистики в существующий сервис: последние 24 часа с почасовым графиком, 7/30/90 дней, визиты, просмотры страниц и статей, заявки, источники переходов и популярные материалы. Палитра, типографика и оформление соответствуют Boykov Services.

Исправлена проверка прав файла на Windows: NTFS использует ACL, поэтому сравнение `stat().mode` с Unix-правами выполняется только на системах с POSIX-правами. На Linux проверяются и файл 0600, и каталог 0700. Проверки содержимого токена, доступа и отсутствия утечки выполняются на всех платформах.

Если предыдущая установка остановилась с `438 !== 384`, повторите команду установки из обновлённого архива: установщик применит только `fix-windows-check.patch` поверх уже установленного раздела. Отменять прежний патч не требуется.

## 1. Локальная установка

Скачайте `Boykov-services_Statistics_Patch.zip` в «Загрузки». Откройте PowerShell в корне локального проекта Boykov Services:

```powershell
$archive = Join-Path $HOME 'Downloads\Boykov-services_Statistics_Patch.zip'
Expand-Archive -LiteralPath $archive -DestinationPath '.\_patch-statistics' -Force
powershell -NoProfile -ExecutionPolicy Bypass -File '.\_patch-statistics\Install-Patch.ps1'
```

Установщик сначала проверяет совместимость всех изменений, сохраняет затрагиваемые существующие файлы в `.git/boykov-patch-backups`, применяет патч и запускает `npm run check`. Ожидается `PATCH_CHECK=OK`. Требуется Node.js 24. Зависимости проекта не менялись.

Патч подготовлен к `main` 9caa570. Он совместим с дополнительным патчем WordPress/Tilda 1.1: файлы коннекторов не затрагиваются. Если версия проекта изменилась и проверка совместимости не прошла, установщик остановится до изменения файлов. Сброс рабочего дерева не нужен.

## 2. Проверка и push

Для локального просмотра используйте обычный запуск проекта. До подключения Метрики посещаемость отмечена прочерками, заявки считаются из локальных данных. Для реальной посещаемости нужен токен Метрики с правом просмотра счётчиков.

После `PATCH_CHECK=OK`:

```powershell
git status --short
git add server/app.js src/App.tsx src/types.ts server/modules/statistics src/pages/Statistics.tsx src/pages/Statistics.css tests/helpers/metrika-fixture.js tests/statistics.test.js docs/STATISTICS.md scripts/deploy-statistics.sh
git commit -m "feat: add website statistics and rolling 24-hour reports"
git push
```

Скрипт не создаёт коммиты и не меняет автора Git. Не добавляйте архив или папку `_patch-statistics` в коммит. Если остались несохранённые изменения предыдущих обновлений, зафиксируйте и отправьте их обычным порядком.

## 3. Установка на VPS Boykov Services

На сервере центрального сервиса, не на серверах подключённых сайтов:

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-statistics.sh
```

Ожидается `STATISTICS_DEPLOY=OK`. Скрипт создаёт согласованную резервную копию БД, сохраняет предыдущий образ, пересобирает только приложение и дожидается здорового состояния. Документы продолжают работать. В выводе будет путь `BACKUP`; внутри него находится `rollback-app.sh` для возврата предыдущего образа без подмены актуальной базы.

## 4. Включение реальных данных

Войдите в сервис под аккаунтом администратора → **Статистика** → выберите сайт → значок настроек → **Подключить доступ**. Нужен один OAuth-токен Яндекс Метрики с правом `metrika:read` для аккаунта, имеющего доступ к нужным счётчикам. В окне есть ссылка на официальную инструкцию получения токена. Пароль Яндекса вводить в сервис не нужно. Не присылайте токен в чат.

Известные счётчики уже указаны; после проверки токена доступные профили подключатся автоматически. Проверьте каждый сайт. Для Энерго 365 включены все поддомены; при отдельных счётчиках укажите все нужные номера. Установка дополнительных плагинов и новые задания Cron не требуются.

Интерфейс проверяет обновления каждые 30 секунд. Полный отчёт посещаемости обновляется раз в две минуты для последних суток и раз в десять минут для длинных периодов. Это не посекундный счётчик: Метрика передаёт данные с задержкой. При сбое сохраняется последний успешный снимок с его интервалом; недоступные данные не подменяются нулями.

Полная инструкция, методика подсчёта и ограничения: `docs/STATISTICS.md` в проекте. Цифры Метрики могут отличаться от встроенной статистики редакции NWD, так как используются разные системы учёта визитов. Заявки берутся из Boykov Services, включая корзину.
