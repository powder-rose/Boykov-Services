# Boykov Services · Статистика из админок

Это замена интеграции с Метрикой на собственные данные сайтов. Дизайн раздела, периоды 24 часа / 7 / 30 / 90 дней, графики и автоматическое обновление сохранены. В комплекте коннекторы NWD, Паспорта доступности и Паспорта безопасности.

## Что действительно подключается

- **NWD:** существующая статистика редакции MySQL — все четыре показателя, источники, страницы и статьи.
- **Паспорт доступности:** собственные таблицы SQLite, включая сопоставление просмотров со статьями каталога.
- **Паспорт безопасности:** существующие визиты и заявки JSONL. Отдельных просмотров страниц в журнале нет: карточки просмотров отмечены прочерком, график визитов работает.

**WordPress и два сайта на Тильде этим патчем не подключаются к статистике.** Они остаются в списке с ожиданием источника, а заявки продолжают показываться из центрального сервиса. Для Энерго 365 нужно название плагина статистики; для Тильды — отдельное решение получения её показателей. Новые счётчики без согласования не добавляются.

## 1. Установка в Windows

Предполагается текущая версия проекта со статистикой, commit 042adae. Предыдущий патч отменять не нужно. Скачайте `Boykov-services_Native_Statistics_Patch.zip` в «Загрузки» и откройте PowerShell в корне локального проекта:

```powershell
$archive = Join-Path $HOME 'Downloads\Boykov-services_Native_Statistics_Patch.zip'
Expand-Archive -LiteralPath $archive -DestinationPath '.\_patch-native-statistics' -Force
powershell -NoProfile -ExecutionPolicy Bypass -File '.\_patch-native-statistics\Install-Patch.ps1'
```

Установщик проверяет совместимость, сохраняет затрагиваемые существующие файлы в `.git/boykov-patch-backups`, применяет изменения и выполняет `npm run check`. При повторном запуске он тоже запускает проверки. Ожидается `PATCH_CHECK=OK` и `fail 0`. Число пропусков зависит от доступности PHP, MySQL и Python в локальной среде; в среде подготовки весь набор проверен с этими зависимостями.

## 2. Commit и push

После успешной проверки:

```powershell
git status --short
git add -- (Get-Content '.\_patch-native-statistics\FILES.txt')
if ($LASTEXITCODE -ne 0) { throw 'Git add failed' }
git commit -m "feat: use native website statistics instead of Metrika"
if ($LASTEXITCODE -ne 0) { throw 'Git commit failed' }
git push
```

В `FILES.txt` перечислены только файлы этого обновления, включая удаляемые файлы прежней интеграции. Установщик не создаёт коммиты и не меняет автора Git. Архив и папку `_patch-native-statistics` в коммит добавлять не нужно. Патч совместим с отдельным обновлением коннекторов WordPress/Tilda 1.1.

## 3. VPS центрального сервиса

На сервере Boykov Services:

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-statistics.sh
```

Ожидается `STATISTICS_DEPLOY=OK`. Создаются резервная копия БД и ссылка на предыдущий образ для отката; пересобирается только `app`. После этого раздел работает с новым протоколом, но посещаемость появится после подключения источников.

## 4. Подключение сайтов

Подробные команды для трёх серверов находятся в `CONNECT-SITES.md` в этом архиве и в `docs/STATISTICS.md` проекта. Установите центральный сервис первым, затем коннекторы источников. Используются существующие серверные ключи доставки заявок; секреты в чат присылать не нужно. Для NWD нужно добавить отдельное задание в CronTab Beget каждую минуту; готовую команду выведет установщик. У двух паспортов работают отдельные службы.

Сайты передают отчёты раз в минуту, интерфейс проверяет обновления каждые 30 секунд. Снимок старше трёх минут отмечается как устаревший. При сбое сохраняется последний успешный отчёт с его исходным временем, а не нулевые показатели.

Данные проверены на воспроизводимых SQLite/JSONL-примерах и настоящем MySQL-совместимом сервере MariaDB. Проверены границы времени, повторная доставка, недопустимые отчёты, авторизация, сохранение после перезапуска и определение путей рабочего backend. В браузере проверены собственный отчёт NWD, график Паспорта безопасности без выдуманных просмотров, таблицы и состояния неподключённых сайтов. Подключение к реальным VPS выполняется по командам после push.
