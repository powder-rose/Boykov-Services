# Собственная статистика сайтов

Раздел «Статистика» получает отчёты из существующих систем учёта сайтов. Яндекс Метрика и её токены для этого раздела не используются. Внешние счётчики на публичных сайтах этим обновлением не изменяются.

## Поддерживаемые источники

| Сайт                    | Откуда берутся данные                                          | Показатели                                                                   |
| ----------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| nwdelectricity.ru       | MySQL редакции: panel_traffic_view, panel_article, feedback    | Визиты, просмотры, статьи, источники, страницы, заявки                       |
| pasport-dostupnosty.ru  | SQLite: analytics_visits, analytics_pageviews, articles, leads | Визиты, просмотры, статьи по каталогу, источники, страницы, заявки           |
| pasport-bezopasnosty.ru | Существующие visits.jsonl и leads.jsonl                        | Визиты с действующим фильтром ботов, источники по сохранённым данным, заявки |

У Паспорта безопасности существующий журнал фиксирует начало визита, а не каждый просмотр страницы. Поэтому просмотры страниц и статей в его отчёте отмечены прочерком; график показывает доступную линию визитов. Входные страницы визитов не выдаются за просмотры всех страниц. Дополнение самого счётчика просмотров — отдельное изменение сайта.

Для energo-365.ru нужно определить плагин статистики WordPress; подключение его истории этим патчем не реализовано. Для boykovgroup.ru и elektrolaboratoriya-techotchet.ru также пока нет подключённой выгрузки встроенной статистики Тильды: её документированный API посвящён экспорту проектов и страниц, а не посещаемости (<https://help-ru.tilda.cc/api>). Эти сайты остаются в селекторе, с явным ожиданием подключения и доступными заявками центрального сервиса. Новые независимые счётчики на них автоматически не устанавливаются.

## Периоды и методика

- **24 часа** — последние скользящие сутки до начала минуты формирования отчёта. График по часам; первый и последний час могут быть неполными. В интервале 16:34–16:34 показаны 25 часовых отрезков суммарно за 24 часа.
- **7, 30, 90 дней** — календарные дни по Москве, включая текущий неполный день.
- Границы всех показателей внутри отчёта совпадают; начало включено, конец исключён.
- Синхронизация сайтов выполняется раз в минуту. Открытый раздел проверяет новые данные каждые 30 секунд; скрытая вкладка и другие разделы не опрашивают отчёты.
- Если отчёт старше трёх минут, показывается предупреждение и последний сохранённый снимок с прежними цифрами и интервалом. Сбой не превращается в нули.

Правила определения визита сохраняются из системы-источника. У NWD это `entry=1` после 30 минут без просмотров, у Паспорта доступности — записи `analytics_visits`, у Паспорта безопасности — записи существующего журнала с тем же фильтром ботов. Общие периоды отчётов приведены к московскому времени; прежний отчёт Паспорта безопасности за «сутки» использовал завершённый календарный день, а новый режим показывает скользящие 24 часа.

После подключения **заявки считаются на стороне сайта**, как в его админке: NWD исключает корзину `feedback.trash`, Паспорт доступности читает текущую таблицу `leads`, Паспорт безопасности — существующий журнал заявок. Число может отличаться от раздела «Заявки» Boykov Services, где есть свои корзина и история доставки. До первого отчёта карточка заявок показывает число из центральной базы, и это подписано отдельно. Заявки центрального сервиса не смешиваются с посещаемостью из другого временного окна.

Просмотры статей NWD определяются сохранённым `article_site_id`, а не догадкой по URL. Для Паспорта доступности просмотр страницы сопоставляется с собственным каталогом статей и сохранёнными псевдонимами. Если каталога нет, показатель недоступен. История ограничена тем, что сохранил источник: новые данные задним числом не создаются.

## Передача и защита данных

Коннекторы запускаются рядом с существующими данными и читают их без изменений. Для SQLite используется транзакция только для чтения, для MySQL — согласованный снимок в транзакции только для чтения, JSONL читается потоком до зафиксированного размера. Незавершённая последняя строка допишется и попадёт в следующую синхронизацию; повреждённая полная строка вызывает ошибку вместо частичного отчёта.

В центральный сервис отправляются только агрегаты за четыре периода: числа, интервалы, очищенные пути страниц и заголовки материалов. IP, идентификаторы посетителей, телефоны, почта и содержимое заявок не передаются. Параметры URL и фрагменты в таблицы не попадают. Отчёт отправляется по HTTPS на `/hooks/statistics/:siteId` с существующим серверным ключом подключения заявок. Он не вставляется в браузер и не выводится в журнал. Генерация нового ключа и перенастройка форм не нужны.

Все четыре периода сохраняются одной транзакцией SQLite. Повторная отправка того же снимка идемпотентна; более старый снимок не заменяет новый. Конфликт содержания за одинаковое время отклоняется. Проверяются источник, домен, интервалы, суммы, состав рядов и безопасные пути. Отчёты привязаны к домену источника и не переходят к другому домену после переименования сайта.

Перед отправкой полный снимок сохраняется в закрытом каталоге состояния. При сетевом сбое он остаётся для повторной доставки. Если временно недоступен исходный файл, можно повторно доставить предыдущий полный снимок, но его исходное время сохраняется: повторная доставка не скрывает устаревание.

## Центральный сервис

Новая таблица: `statistics_native_reports`. Прежние таблицы кэша и настройки Метрики не используются, но не удаляются. Файл прежнего токена, если он существовал, не читается и не требуется. Заявки, документы, аккаунты и коннекторы продаж не изменяются.

GET `/api/statistics/sites` и GET `/api/statistics/report?site=ID&period=24h|7|30|90` требуют входа. Ответы: `Cache-Control: private, no-store`. Информация о подключении доступна администратору в окне настроек; общие и личные аккаунты могут смотреть отчёты.

POST `/hooks/statistics/:siteId` требует действующий ключ источника. Обычная пользовательская сессия не заменяет этот ключ. Старые маршруты подключения Метрики удалены.

После push на VPS Boykov Services:

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-statistics.sh
```

Скрипт сохраняет согласованную копию SQLite и предыдущий образ, пересобирает только `app`, ждёт healthcheck и проверяет новую таблицу и закрытость API/приёмника. Ожидается `STATISTICS_DEPLOY=OK`. Обратный образ можно включить через `BACKUP/rollback-app.sh`; рабочая база не подменяется старой копией.

## Подключение источников

Подключайте после установки новой версии центрального сервиса. Готовые скрипты используют уже работающие настройки доставки заявок. Они не останавливают эти коннекторы и не меняют обработчики форм.

### NWD — Beget

В SSH под пользователем хостинга:

```bash
git clone --depth 1 https://github.com/powder-rose/Boykov-Services.git "$HOME/.nwd-production/native-statistics-source"
cd "$HOME/.nwd-production/native-statistics-source"
bash scripts/install-native-statistics-nwd.sh
```

Скрипт использует `/usr/local/bin/php7.3` и существующий `$HOME/.nwd-production/boykov-leads/config.php`, копирует две PHP-программы в отдельный закрытый каталог, проверяет первую отправку и выводит `NWD_STATISTICS_CRON_COMMAND=...`.

В Beget → CronTab добавьте **новое** задание с выведенной командой и расписанием `* * * * *`: каждую минуту, каждый час, каждый день. Существующее задание доставки заявок сохраните. Ожидается `NWD_STATISTICS_CONNECTION=OK`; без задания Cron первая отправка не обеспечит дальнейшее обновление.

### Паспорт доступности — его VPS

```bash
git clone --depth 1 https://github.com/powder-rose/Boykov-Services.git /opt/boykov-native-statistics-source
cd /opt/boykov-native-statistics-source
bash scripts/install-native-statistics.sh accessibility
```

Скрипт проверяет контейнеры `accessibility-passport-app-1` и `boykov-leads-accessibility-delivery-1`, берёт существующий ключ из окружения агента, подключает постоянный каталог данных сайта только для чтения и запускает отдельный контейнер `boykov-native-statistics-accessibility-collector-1` на уже имеющемся образе Node. Исходный сайт не пересобирается и не перезапускается. Ожидается `NATIVE_STATISTICS_CONNECTION=OK SOURCE=accessibility`.

### Паспорт безопасности — его VPS

```bash
git clone --depth 1 https://github.com/powder-rose/Boykov-Services.git /opt/boykov-native-statistics-source
cd /opt/boykov-native-statistics-source
bash scripts/install-native-statistics.sh security
```

Скрипт определяет процесс, слушающий 8787, пользователя приложения, `PASSPORT_PROJECT_ROOT`, `SERVER_ENV_FILE` / `.env.server` и существующие пути `VISITS_FILE`/`LEADS_FILE`. Ключ берётся из `/etc/boykov-leads-security.env`. Запускается отдельная служба `boykov-native-statistics-security.service` под пользователем сайта. PM2 и сайт не перезапускаются.

Если выведено `NATIVE_SOURCE_FILE_NOT_FOUND`, установка остановлена до изменения работающих служб. Выведенные пути можно сверить с фактическим расположением файлов и передать явно:

```bash
bash scripts/install-native-statistics.sh security /полный/путь/visits.jsonl /полный/путь/leads.jsonl
```

Ожидается `NATIVE_STATISTICS_CONNECTION=OK SOURCE=security`. Каталог резервной копии конфигурации выводится как `NATIVE_BACKUP`. Если настройки подключения заявок имеют иной формат, скрипт остановится с `NATIVE_EXISTING_LEADS_CONNECTION_NOT_FOUND`; значения ключей присылать не нужно.

Если каталог клона уже существует, используйте его с `git pull --ff-only` вместо повторного `git clone`, предварительно проверив отсутствие своих изменений. На серверах двух разных сайтов одинаковое имя каталога допустимо.

## Диагностика

```bash
# Паспорт доступности
docker compose -f /opt/boykov-native-statistics-accessibility/compose.json ps
docker compose -f /opt/boykov-native-statistics-accessibility/compose.json logs --tail 20

# Паспорт безопасности
systemctl status boykov-native-statistics-security.service --no-pager
journalctl -u boykov-native-statistics-security.service -n 20 --no-pager
```

Логи показывают код результата и время снимка. Ошибка синхронизации не меняет последний отчёт и не останавливает приём заявок.

Разработка: `npm run check`. Тесты MySQL включаются при наличии `PHP_BIN` и `NATIVE_TEST_MYSQL_PORT`; локально на Windows этот дополнительный тест пропускается без MySQL. Основные проверки API, SQLite, JSONL, повторной доставки и границ времени выполняются без внешних сервисов.
