# Boykov Group на Tilda

## Обновление Boykov Services

После установки локального патча выполните `npm run check`, закоммитьте и
отправьте изменения в свой GitHub. На VPS Boykov Services (cv8356425):

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-tilda.sh
```

Скрипт делает онлайн-снимок `platform.sqlite` и сохраняет предыдущий Docker-образ,
затем собирает и перезапускает только `app`. После запуска проверяются healthcheck,
миграция, источник boykovgroup.ru и ответ 401 без ключа. Данные трёх действующих
подключений сохраняются. Результат: `TILDA_DEPLOY=OK` и путь `BACKUP`.
В каталоге резервной копии создаётся `rollback-app.sh`: он возвращает предыдущий
образ приложения, сохраняя текущую базу и поступившие после обновления заявки.

## Настройка Tilda

1. В боевом Boykov Services откройте «Заявки» → «Бойков Групп» →
   «Создать ключ подключения». Сохраните показанные адрес и API Key.
   Ключ отображается один раз; при замене старый сразу перестаёт работать.
2. В Tilda откройте **boykovgroup.ru → Настройки сайта → Формы → Webhook**.
3. Укажите **Webhook URL** из Boykov Services. Обычно это
   `https://boykov-services.ru/hooks/tilda/boykovgroup`; если домен уже был
   добавлен вручную, используйте адрес из карточки, его ID может отличаться.
4. В дополнительных настройках передачи API-ключа:

   | Поле | Значение |
   | --- | --- |
   | API Method | HEADER — передача в заголовках |
   | API Name | Authorization |
   | API Key | Значение из Boykov Services целиком: `Bearer ` и 64 символа ключа |

5. Название в списке: **Boykov Services — заявки**. Отправку Cookie оставьте
   выключенной. «Отправлять только после оплаты» тоже выключите, чтобы
   получать обращения до покупки. Поддерживаются стандартная отправка формы и JSON.
6. Сохраните приёмщик. Tilda отправит `test=test`, сервис ответит 200, а карточка
   сменится на «Webhook подтверждён». Этот тест не создаёт заявку.
7. Назначьте приёмщик всем нужным формам. Если Tilda предложит назначить его всем
   формам сразу, воспользуйтесь этим. Проверьте чекбокс Webhook в «Контенте»
   каждой формы, включая попапы, корзину, квизы и формы на отдельных страницах.
8. Опубликуйте затронутые страницы, затем отправьте пробную заявку с каждой
   формы. В Boykov Services проверьте контакты, дополнительные поля и сайт.
   Не отключайте существующую доставку на почту или в CRM.

Пароль Tilda и ключ не нужно присылать в переписку. Ключ вводится в настройках
приёмщика, в публичный код формы он не добавляется.

## Что сохраняется

Идентификатор — `tilda:` + `tranid` из Tilda. Контакты, услуга, сообщение и
название формы распознаются по распространённым русским и английским именам
переменных. Все остальные поля остаются в карточке с исходным именем, включая
UTM и товары. Массивы и вложенные объекты сохраняются как JSON с устойчивым
порядком ключей. Cookie исключены. Нестандартные имена переменных не теряют
значения: если контакт не распознан в кратком списке, он доступен в полях формы.
Длинные значения остаются в дополнительных полях; краткие поля ограничены
размерами действующей модели (имя 200, телефон 80, сообщение 12000 символов).
Максимум — 100 полей по 16000 символов и тело 128 КБ. Превышение возвращает
ошибку; оно не подтверждается как успешная доставка.

Дата для сортировки — время первого приёма в Boykov Services: документированный
Webhook Tilda не содержит отдельного обязательного времени отправки. В интерфейсе
время показывается по Москве. Адрес страницы берётся из Referer только своего
домена; при его отсутствии используется главная страница сайта.

Ответ 200 отправляется после COMMIT SQLite с `synchronous=FULL`. Повтор по
`tranid` возвращает ту же заявку, не меняет время первого приёма, статусы,
комментарии и историю отдела продаж. Другие данные под тем же `tranid` дают 409,
сохранённое обращение не перезаписывается. Разные номера не склеиваются по
телефону или почте. Ошибка формата или конфликт показываются в подключении;
следующая успешная доставка снимает предупреждение.

## Контроль доставки

«Webhook подтверждён» означает, что приёмщик принял авторизованную проверку
или заявку. Это не постоянный мониторинг Tilda и не проверка назначения всем
формам. У Tilda нет heartbeat агента, поэтому простой без заявок не вызывает
ложную ошибку «Нет сигнала». В карточке отдельно видно последнее поступление.

Tilda ожидает ответ за пять секунд. После неудачи она делает ещё две попытки
через минуту; это ограниченное число повторов. Долгая недоступность VPS требует
сверки раздела «Заявки» и журнала ошибок в Tilda с Boykov Services. Сохраняйте
штатные уведомления как резерв. Новые формы тоже нужно назначать приёмщику и
проверять после публикации. Старые заявки Tilda автоматически не импортируются.

Официальная документация: https://help-ru.tilda.cc/forms/webhook.
