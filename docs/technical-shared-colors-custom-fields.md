# Техотдел — читаемая таблица, общие цвета и добавляемые поля

Это локальный патч к **Boykov-services** после успешного импорта Google Apps Script и установки обновления «Полная таблица». **Не заменяет проект и не меняет Google Таблицы**.

## Точная логика

- **Существующие семь вкладок и все исходные столбцы остаются на месте**, в том же порядке и с теми же данными.
- **Зебра строк:** белый / лёгкий серый; при наведении строка подсвечивается.
- **Длинные тексты автоматически переносятся**, высота строки растёт. Для длинных защищённых комментариев есть просмотр всего текста отдельным окном.
- **Ширина** управляется перетаскиванием границы заголовка, кнопками и автошириной. Сохраняется **только в браузере** с помощью localStorage, отдельно для каждой вкладки/колонки. У других сотрудников настройка ширины не меняется.
- **Цвет** (нет, жёлтый, голубой, зелёный, розовый) хранится **в общей базе SQLite**. Изменения видят все пользователи этого Boykov-services после обновления интерфейса (сейчас автоматический опрос каждые 30 секунд).
- **Добавить поле:** кнопка над таблицей. Задайте название — новое **редактируемое** рабочее поле появится в конце текущей вкладки для всех сотрудников. Вместо заранее созданных пустых столбцов показываются только существующие и явно добавленные.
- Сохраняются **до 50 видимых рабочих столбцов** на вкладку. Если оригинал содержит 30 столбцов, можно добавить до 20 своих. Названия не должны дублироваться.
- Значения новых полей, имя, указанное сотрудником, и история правок сохраняются **в собственной SQLite**, отдельно от Google. При повторной синхронизации все сохраняется. Поля можно добавлять на любой из семи вкладок.
- **Защита бухгалтерии сохранена:** поля, зеркалируемые из бухгалтерии, по-прежнему не редактируются. Даже прямой запрос к API не может изменить бухгалтерскую колонку через обычный метод.
- **Вход в техотдел отдельно не нужен:** действует общий вход Boykov-services, имя автора можно указать по желанию.

## Установка в Windows PowerShell

Скачайте архив и распакуйте его в «Загрузки». В PowerShell:

```powershell
$zip = "$env:USERPROFILE\Downloads\Boykov-services_Tech_Shared_Colors_Custom_Fields_Patch.zip"
$folder = "$env:USERPROFILE\Downloads\Boykov-services_Tech_Shared_Colors_Custom_Fields_Patch"
Expand-Archive -LiteralPath $zip -DestinationPath $folder -Force
node "$folder\apply-update.mjs" "C:\Users\user\WebstormProjects\boykov-services"
```

Или из папки распакованного архива:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\apply-update.ps1 -ProjectPath "C:\Users\user\WebstormProjects\boykov-services"
```

Если PowerShell не прочитал кодировку, используйте вариант `node` выше — он независим от кодовой страницы Windows PowerShell.

Затем:

```powershell
cd "C:\Users\user\WebstormProjects\boykov-services"
npm run check
npm run dev
```

Проверка интерфейса: откройте «Техотдел» → найдите длинный комментарий (переносится на строки) → смените ширину → смените цвет → проверьте цвет в другом браузере → добавьте поле «Следующий выезд» и заполните его у тестовой записи. После обновления страницы и повторной синхронизации поле и значение должны остаться.

## Резервная копия и защита от перезаписи

- Установщик проверяет **SHA-256 исходных файлов** проекта перед любым изменением. Если текущие файлы не совпадают с проверенной версией, выводит `VERSION_MISMATCH` и **ничего не меняет**.
- Резервные копии четырёх файлов (до замены) кладутся в `C:\Users\user\boykov-services-backups\tech-shared-columns-*`.
- `.env`, SQLite, Docker volumes, сервис документов, Wordstat и проект Apps Script не редактируются.
- Установщик не выполняет `git push`, деплой или изменение живых Google-данных.
- Новые таблицы SQLite создаются автоматически при старте приложения. До деплоя сделайте резервную копию рабочего тома.
- На VPS достаточно обновить приложение `app` после проверки `npm run check`, не удаляя том `platform-data`.

## Список новых методов API (только внутри общего авторизованного `/api`)

- `POST /api/technical/tabs/:id/columns` — создать рабочее поле `{ "title": "Дата выезда" }`.
- `PATCH /api/technical/tabs/:id/columns/color` — сохранить общий цвет `{ "columnKey": "sheet:6", "color": "green" }`.
- `PATCH /api/technical/tabs/:id/rows/:key/custom/:columnId` — сохранить значение нового поля `{ "value": "15.12", "author": "Ирина" }`.
- `GET /api/technical/meta` — добавлены общие цвета и метаданные новых полей.

Все эти методы защищены **существующей сессией Boykov-services**, заголовком запроса и проверкой допустимых значений. Публичного API для редактирования бухгалтерских значений нет.
