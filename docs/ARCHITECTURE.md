# Архитектура

React + Vite + TypeScript отвечает за интерфейс. Express на Node.js 24 — единая точка доступа: авторизация, реестр задач, API Wordstat и проксирование запросов документов. FastAPI — приватный адаптер исходного Python-ядра договоров. Встраивания iframe и запуска Telegram/MAX нет.

## Основные файлы

| Путь | Содержимое |
| --- | --- |
| `src/App.tsx` | Навигация, вход и общий каркас |
| `src/pages/` | Обзор, договоры, Wordstat, история и настройки |
| `src/api.ts` | Единый клиент API, обработка истечения сессии |
| `server/auth.js` | Пароль, SQLite-сессии, CSRF, лимит входа |
| `server/app.js` | Защищённые API и композиция модулей |
| `server/modules/wordstat/` | Исходная логика сбора, контрольные точки и Excel |
| `server/worker-client.js` | Внутреннее соединение с Python по токену |
| `worker/service.py` | HTTP API документов, очередь, история, валидация и файловые результаты |
| `worker/ser_one_time.py` | Заполнение строк приложения №1 разового договора СЭР с сохранением VBA |
| `worker/vendor/core/` | Python-ядро и реальные Word-шаблоны из исходного бота |
| `shared/templates.json` | Общий список шаблонов интерфейса и worker |

## Документы

1. Браузер передаёт исходный текст или файл в защищённый API.
2. Node передаёт запрос во внутренний Python-сервис с токеном.
3. Worker сохраняет задачу в SQLite и обрабатывает её в отдельном потоке. HTTP-запрос возвращает ID, а не ожидает ответа ИИ.
4. Исходное ядро обращается к YandexGPT / OCR. Пользователь видит и исправляет реквизиты.
5. Новая задача генерации проверяет данные, резервирует номер и заполняет исходный DOCM. Написание чисел словами выполняется детерминированно, без отдельного платного обращения к ИИ.
6. Файл доступен только через защищённый API. Исходная загрузка удаляется после распознавания.

Один Python-worker сериализует обращения к ядру и нумерации. Request ID предотвращает повторное создание одного документа при сетевом повторе запроса. После перезапуска незавершённая задача помечается ошибкой. Номер мог быть зарезервирован до прерывания; пропуск номера допускается, повторная выдача — нет в рамках работающего worker.

`ser_one_time` принимает от одной до девяти строк `one_time_services`: `name`, `working_days`, `quantity`, `price`. Worker вычисляет стоимость как сумму `quantity * price`, заполняет приложение №1 и удаляет незаполненные строки. Общие реквизиты используют существующие 20 автозамен. VBA и кнопка взяты из рабочего `template2.docm`; пересборка из пользовательского DOCM доступна через `scripts/prepare-ser-one-time.py`.

В обслуживании СЭР первый месяц периода всегда совпадает с месяцем заключения договора. Это правило едино для автозамен 022 (период обслуживания) и 028 (строка счёта).

## Wordstat

Полный ответ на каждую фразу сохраняется до продвижения счётчика. При продолжении ответы перечитываются с диска; повторно запрашиваются только отсутствующие. XLSX записывается во временный файл с последующим rename. HTTP 429 ставит задачу на ожидание `Retry-After`; ошибки ключа отражаются в результатах и не связаны с входом в платформу.

## Добавление сервиса

Создайте модуль в `server/modules/<service>/`, страницу в `src/pages/`, добавьте пункт навигации и карточку обзора. Зарегистрируйте API **после** `installAuth` и **до** завершающего `/api` 404. Для фоновых задач сохраняйте состояние до выполнения внешних запросов. Не используйте секреты в `VITE_*`. Новые внешние интеграции могут работать отдельным worker в Compose и подключаться через общий API.

## Production

Один origin для frontend и API; Vite proxy в разработке воспроизводит эту схему. Одна HttpOnly/SameSite=Strict cookie, хеш пароля и токен worker только на сервере. Запросы изменения требуют собственного заголовка и проверенного Origin. SQLite хранит SHA-256 от случайного сессионного токена. Смена хеша пароля инвалидирует прежние сессии при запуске. Docker запускает приложение без root; Worker не публикуется наружу.

Существующие базы бота и Wordstat автоматически не импортируются. Счётчики нумерации не синхронизируются с Telegram/MAX. Номера договоров состоят из первых двух букв фамилии в верхнем регистре, даты и порядкового номера без дополнительного префикса. Пользовательские роли и корпоративный SSO — возможный следующий модуль.
