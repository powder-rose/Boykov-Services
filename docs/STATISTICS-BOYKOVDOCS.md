# Статистика BoykovDocs

BoykovDocs — самостоятельный источник в разделе «Статистика», без создания
нового сайта в «Заявках». Он появляется в общем графике и в выборе сайта.

Агент читает существующий журнал `/app/src/data/analytics/visitor-events.jsonl`
в отдельном контейнере с монтированием каталога только для чтения.
Новый счётчик, правки BoykovDocs и перезапуск его приложения не требуются.
История начинается с первой сохранённой записи; периоды до неё не
отображаются как нулевая посещаемость на графике.

Одна строка журнала — один просмотр. Новый визит начинается при первом
просмотре посетителя или после 30 минут без активности; это число сессий,
а не число уникальных посетителей из собственной админки BoykovDocs.
Временные интервалы совпадают с остальными отчётами: последние 24 часа
по часам и 7, 30, 90 календарных дней по Москве.
Журнал не содержит URL, реферер или признак статьи: соответствующие показатели
недоступны. Регистрации, покупки, пополнения остаются в «Клиенты BoykovDocs».

На центральный сервер отправляются только агрегированные числа. Хеши
посетителей не передаются и не сохраняются в состоянии агента.
Используется существующий приватный ключ подключения клиентов; ключ не выводится.
Агент проверяет подтверждение сервера, сохраняет неизменный пакет
для повторной доставки в пределах минуты, при следующей минуте строит
новый отчёт. При ошибке чтения, повреждённой завершённой строке или сокращении
истории он не заменяет отчёт недостоверными данными. Последний отчёт остаётся
в сервисе с отметкой устаревания. Ограничения чтения: 256 МиБ исходного
журнала и 500 000 событий в расчётном окне.

## Установка

После коммита и push в main, на VPS Boykov Services (cv8356425):

```bash
cd /opt/boykov-services
git pull --ff-only origin main && bash scripts/deploy-boykovdocs-statistics.sh
```

На VPS BoykovDocs (cv8367491):

```bash
cd /opt/boykov-services-connector
git pull --ff-only origin main && bash scripts/install-boykovdocs-statistics.sh
```

Ожидаемый результат: `BOYKOVDOCS_STATISTICS_CONNECTION=OK`.
Установка использует уже существующее подключение клиентов.

На центральном VPS:

```bash
cd /opt/boykov-services
bash scripts/check-boykovdocs-statistics.sh
```

Ожидается `status: CONNECTED`, `periods: 4`. При проблеме передачи на VPS BoykovDocs:

```bash
docker compose -f /opt/boykovdocs-statistics-delivery/compose.json ps
docker compose -f /opt/boykovdocs-statistics-delivery/compose.json logs --tail 20 delivery
```

Не выводите конфигурационный файл с ключом. Скрипты установки и центрального
деплоя создают резервные копии; остальные агенты и базы данных не меняются.

## Обновлённый сбор событий v2

Агент поддерживает прежние строки журнала и новые строки с `schema: 2`.
В новых строках `eventId` — хеш идентификатора доставки. Повтор такого события
не увеличивает просмотры; количество исходных строк для проверки целостности
истории при этом сохраняется. Некорректная завершённая строка v2 останавливает
обновление отчёта, оставляя последний достоверный пакет.

`filteredSince` — время первого завершённого события v2. Центральный сервис
передаёт его в интерфейс вместе с пояснением, что более ранняя история записана
по прежним правилам. Исторические просмотры не удаляются и не объявляются
достоверно человеческими. Квитанции, хеши посетителей и event ID в пакет не входят.

24 часа остаются скользящим окном завершённых минут; это не календарное «Сегодня».
Собственная фильтрация не обещает полного совпадения с Яндекс Метрикой.
