# Энерго 365: собственная статистика WordPress

Плагин `boykov-leads` версии 1.2.0 добавляет посещаемость к существующей доставке заявок. Поддерживается обычный WordPress и сетевая активация Multisite. Один источник `energo-365.ru` объединяет основной сайт и его поддомены, включая вложенные. Другие домены сети исключены. В таблицах популярных страниц сохраняется фактический домен.

## Установка

1. Применить патч к Boykov Services, выполнить `npm run check`, закоммитить и отправить изменения.
2. На VPS Boykov Services выполнить `git pull --ff-only origin main` и `bash scripts/deploy-wordpress-statistics.sh`. Скрипт проверяет чистоту отслеживаемых файлов, сохраняет предыдущий образ и резервную копию SQLite, обновляет только `app` с ожиданием healthy. Путь резервной копии и команда отката сохраняются на сервере. Факт получения WordPress-отчёта эта проверка не подтверждает.
3. В WordPress открыть «Управление сетью → Плагины → Добавить → Загрузить плагин». Выбрать **внутренний** архив `boykov-leads-wordpress.zip` из комплекта обновления. Подтвердить замену установленного плагина. Не удалять старый плагин перед заменой. Для Multisite он должен оставаться активным для сети.
4. В админке основного `energo-365.ru` открыть «Настройки → Boykov Services». Существующие адрес приёма, ключ и очередь заявок сохраняются. Открытие админки запускает обновление схемы без повторной активации плагина.
5. Очистить Autoptimize и кэш страниц, если он используется. Счётчик автоматически исключён из объединения Autoptimize. Открыть публичные страницы и поддомен в приватном окне **без входа в WordPress**. Выйти из WordPress в обычном браузере недостаточно, если страница уже открыта: её нужно перезагрузить.
6. Через минуту в блоке «Посещаемость · Энерго 365 и поддомены» должна обновиться «Подтверждённая доставка». Можно нажать «Отправить статистику и проверить». Текущая незавершённая минута попадёт в следующий отчёт. Проверить «Статистика → Отчёт по сайту → Энерго 365 → 24 часа» и общий график.

Дополнительное задание хостинга не требуется: используется уже настроенный ежеминутный запуск WP-Cron основного сайта. Новая задача статистики отделена от доставки заявок. Не изменять существующую cron-команду заявок. Если прошло несколько минут, а время доставки не меняется, нужны код ошибки из нового блока и время последнего запуска, без ключей.

## Показатели

- Визит: сеанс браузера с 30 минутами бездействия. Cookie с непрозрачным случайным ID действует на основном домене и поддоменах. Переход на поддомен в том же сеансе не создаёт второй визит.
- Просмотр: открытие видимой публичной страницы. Повторная загрузка считается новым просмотром; повторная доставка одного события — нет. Возврат страницы из bfcache считается просмотром.
- Статья: просмотр записи WordPress типа `post`; страницы и произвольные типы записей не выдаются за статьи.
- Источник: `utm_source`, домен перехода, прямой или внутренний переход. Полный referer и параметры URL не сохраняются и не передаются.
- Заявки: записи существующих очередей форм всех подходящих сайтов, включая уже доставленные. Их даты хранятся в UTC; агрегация не зависит от MySQL session time_zone. Старые заявки могут присутствовать в периоде, даже когда посещаемость ещё не собиралась.
- Периоды: последние 24 часа по часам; 7, 30, 90 календарных дней по Москве с текущим неполным днём. Отчёт заканчивается на границе завершённой минуты.

Учёт посещаемости начинается **с установки**. Никакая прежняя посещаемость не восстанавливается из заявок или количества записей. Дата начала видна в сервисе; на графике до неё — пропуск, в таблице по дням — прочерк. Сохраняются ранее подключённые отчёты NWD и обоих паспортов.

Счётчик не учитывает вошедших пользователей WordPress, 404, предпросмотр, feed/trackback, DNT/GPC и распознаваемых по User-Agent роботов. Блокировщики, отключённый JavaScript/cookie, неверное время на устройстве и отсутствие сети могут влиять на цифры: это посещаемость браузеров, а не гарантированный журнал всех HTTP-запросов и не уникальные физические лица. Для сеанса используется cookie; это следует отразить в действующем описании счётчиков сайта.

## Доставка и хранение

Браузер сохраняет неподтверждённый просмотр локально и повторяет отправку до 24 часов. Событие имеет UUID; в WordPress есть уникальный ключ и проверка неизменности данных. Подписанные метаданные страницы связаны с сайтом сети и доменом, не истекают из-за кэширования страницы и не содержат ключ подключения к Boykov Services. Приложение отправляет полный согласованный снимок всех четырёх периодов. Снимок одной минуты сохраняется перед отправкой и повторно используется в эту минуту; следующая минута пересчитывается по журналу, поэтому сбой доставки не теряет предыдущие просмотры.

Используются отдельные глобальные таблицы `boykov_statistics_views`, `boykov_statistics_sessions`, `boykov_statistics_rate` с разграничением `network_id`, InnoDB, транзакциями и блокировками. Журнал просмотров хранится 93 дня, псевдонимы сеансов — 94 дня, ограничители частоты — час. IP в таблицы не записывается; для ограничения запросов используется часовой журнал HMAC минутного сочетания адреса и времени. Очереди заявок не очищаются и не меняются.

Каждый отчёт проверяет наличие и схему очередей всех соответствующих поддоменов. Отсутствующая таблица не подменяется пустой и не даёт успешного отчёта с частичными данными. Неподтверждённая доставка видна в WordPress; в сервисе отчёт старше трёх минут помечается устаревшим. Ложные ACK, неверный siteId или generatedAt не засчитываются. Ключ остаётся в серверных настройках; для статистики используется тот же ключ и отдельный защищённый маршрут `/hooks/statistics/:siteId`.

## Проверки

`npm run check` проверяет центральный сервис и браузерную очередь. При наличии PHP ≥7.3 выполняются проверки подписей, периодов, сетевого отправителя, повторов, отчётов и транзакций на SQLite через ограниченный адаптер диалекта. Он не заменяет проверку MySQL. Для настоящего MySQL заданий нужен отдельный тестовый сервер, `WP_TEST_MYSQL_PORT` или `WP_TEST_MYSQL_SOCKET` и имя `WP_TEST_MYSQL_DATABASE=boykov_wp_test_<suffix>`; эти тесты создают и удаляют только тестовые таблицы. Не направлять их на рабочую базу. Без тестового MySQL соответствующий тест пропускается.

Сборка плагина воспроизводится командой `node scripts/package-wordpress-plugin.mjs`; результат в `_patch-wordpress-statistics/boykov-leads-wordpress.zip`. Архив содержит только исходники плагина, без ключей, пользовательских данных и `node_modules`.
