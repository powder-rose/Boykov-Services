# Фото в PDF — инструмент техотдела

«Техотдел → Фото в PDF → Открыть конвертер» открывает рабочее окно в стилистике Boykov Services. Фотографии можно добавить выбором файлов или перетаскиванием, отсортировать по имени, развернуть порядок, переместить кнопками либо перетащить в списке. Один снимок — одна страница PDF. Таблицы техотдела остаются открыты под инструментом; сочетания отмены таблицы и глобального поиска при открытом диалоге не срабатывают.

## Приватность

Вся обработка выполняется в браузере: File API, ImageBitmap/Canvas, локальный PDF writer. Файлы не передаются HTTP-запросами в API сервиса, на внешние сервисы или CDN; серверного маршрута конвертации нет. Отдельных npm-зависимостей, внешних скриптов и библиотек не добавлено. Настройки, фото и результат не записываются в localStorage, IndexedDB, базу, историю задач или серверную файловую систему. Предпросмотр и скачивание используют временные Object URL. Закрытие окна прекращает обработку, освобождает ссылки и очищает список; повторное открытие начинает новый сеанс. Исходные файлы на устройстве не меняются. Скачанный по кнопке PDF остаётся на устройстве пользователя.

Vite собирает отдельный same-origin worker; обработка идёт в фоне и последовательно декодирует по одному снимку. В браузерах без Worker/OffscreenCanvas есть локальный Canvas fallback. Отмена завершает worker; fallback проверяет AbortSignal между этапами. Ошибка одного изображения останавливает сборку: неполный PDF не выдаётся и страницы не пропускаются молча. Настройки и перестановка фото сбрасывают устаревший результат, а изменение имени позволяет переименовать готовый PDF без пересборки.

В production CSP добавлено только `blob:` в `img-src` для локального предпросмотра. Разрешения для скриптов и соединений остаются same-origin. Документ содержит только JPEG-изображения, страницы и их геометрию, без JavaScript, вложений и EXIF исходных фото.

## Форматы и параметры

- JPG, PNG, WEBP, BMP, AVIF; HEIC/HEIF зависят от поддержки декодера браузера. Если файл не открывается, нужно сохранить его как JPG/PNG.
- Сигнатура растрового формата проверяется до предпросмотра: HTML/SVG, переименованные в JPG, не принимаются.
- До 500 снимков в одном PDF, не больше 50 МБ на входной файл. Неподходящие файлы перечисляются явно; подходящие сохраняются в списке.
- Режимы: компактный 1200 px / 52%, сбалансированный 1600 px / 68%, чёткий текст 2200 px / 83%, высокое качество 3000 px / 90%. При ручном изменении появляется «Свои настройки».
- Максимальная сторона 1200/1600/2200/3000 px или исходное разрешение; JPEG 35–95%. Маленькие снимки не увеличиваются.
- A4 с автоматической ориентацией и полем 18 pt либо страница по пропорциям фото без полей. Геометрия сохраняет весь снимок без растяжения/обрезки; поворот камеры учитывается декодером, прозрачность заменяется белым фоном.
- Защита Canvas: выход не больше 16384 px по стороне и 64 млн пикселей. PDF ограничен 250 МБ; при превышении предлагается уменьшить разрешение или разделить набор. Объём и скорость также зависят от памяти устройства.
- Сжатие не гарантирует уменьшение любого исходного файла: для уже компактных фото или PNG итоговый PDF может быть больше. Показаны реальные размеры и процент изменения.

## Боковая панель

Закреплённая боковая панель ограничена высотой viewport (`100dvh`, fallback `100vh`), прокручивается отдельно по вертикали и не сжимает дочерние блоки. Нижние пункты, помощь, профиль и выход доступны на невысоком экране. Предусмотрен safe-area inset; горизонтального скролла нет. Цвет полосы прокрутки соответствует панели.

## Установка и деплой

Применить патч PowerShell-установщиком в корне локального проекта, выполнить проверки, затем коммит/push обычным способом. База патча — main `14092a0` или совместимая версия. Установщик сохраняет копию изменяемых файлов в `.git/boykov-patch-backups`, сначала выполняет `git apply --check`, затем `npm run check`; повторный запуск проверяет установленный патч без повторного наложения.

После push на VPS Boykov Services:

```bash
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-photo-pdf.sh
```

Скрипт сохраняет предыдущий образ и команду отката в `BACKUP=...`, пересобирает только `app`, ждёт healthy, проверяет HTTP, CSP и наличие worker в production-сборке. Дополнительных сервисов, миграций данных, ключей или cron не нужно. Коннекторы сайтов и сервис документов не перезапускаются. Команда отката при необходимости — `bash <BACKUP>/rollback-app.sh`.

Проверки: `npm run check`; `tests/photo-pdf.test.js` проверяет геометрию, точные бинарные xref/stream offsets, порядок/целостность PDF, лимиты, сигнатуры, имена Windows и production CSP. В браузере проверяются реальный выбор/сортировка фото, режимы, скачивание, поворот EXIF, белый фон PNG, повреждённый снимок, отмена и очистка при закрытии; скачанный PDF дополнительно проверяется независимым PDF-парсером и рендерером. Скрипт деплоя проверяется `bash -n`; фактическое обновление VPS выполняется пользователем.
