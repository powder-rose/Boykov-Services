# Статистика сайтов

Раздел «Статистика» объединяет посещаемость из Яндекс Метрики и заявки, принятые Boykov Services. Он доступен после входа с общим паролем или под личным аккаунтом. Подключения настраивает только администратор.

## Периоды и обновление

- **24 часа** — скользящие последние сутки до начала текущей минуты, график по часам. Первый и последний час могут быть неполными. Например, интервал 18.11 16:34–19.11 16:34 содержит 25 подписанных часовых отрезков, суммарно ровно 24 часа.
- **7, 30 и 90 дней** — календарные дни, включая текущий неполный день; график по дням.
- Все даты, границы и подписи — по Москве (UTC+3).
- Открытый раздел проверяет данные каждые 30 секунд. Полный отчёт Метрики обновляется раз в две минуты для суток и раз в десять минут для остальных периодов. Вкладка в фоне и закрытый раздел не опрашивают API.
- Кнопка «Обновить» проверяет доступный отчёт и настройки. Она использует общий серверный кэш и не обходит его срок жизни.

Четыре показателя: визиты, просмотры страниц, просмотры статей и заявки. Под графиком можно раскрыть таблицу по часам или дням. Отдельно показаны источники визитов, популярные страницы и статьи.

## Первое подключение

1. Войдите под личным аккаунтом администратора. Если он ещё не создан, на VPS выполните `docker compose exec app node server/manage-accounts.js init-admin` в `/opt/boykov-services` и следуйте подсказкам. Существующий аккаунт менять не нужно.
2. Получите OAuth-токен аккаунта Яндекса с доступом на просмотр нужных счётчиков. Достаточно права **`metrika:read`**. Инструкция Яндекса: <https://yandex.ru/dev/metrika/ru/intro/authorization>.
3. В разделе «Статистика» выберите сайт, нажмите значок настроек и вставьте токен в поле «Токен Метрики». Вставляйте только значение, без слова `OAuth`.
4. Нажмите «Подключить доступ». Сервис проверит токен через API. Известные номера счётчиков подключатся автоматически, если все они доступны этому аккаунту.
5. Проверьте номера счётчиков, поддомены и разделы статей для каждого сайта. При необходимости измените и сохраните настройки. Список доступных счётчиков можно раскрыть в том же окне.

Токен вводится непосредственно в сервисе: не добавляйте его в Git, переписку или снимки экрана. Он хранится только на сервере в `data/statistics/metrika.json` (каталог 0700, файл 0600), внутри постоянного Docker-тома. В ответах API и интерфейсе сохранённое значение не возвращается. Замена токена очищает кэш и заново проверяет доступность настроенных счётчиков.

Для получения токена создайте OAuth-приложение в интерфейсе Яндекса «Для доступа к API или отладки», добавьте разрешение `metrika:read`, затем откройте ссылку авторизации из официальной инструкции с ClientID своего приложения. Авторизуйте именно аккаунт, которому выдан доступ к счётчикам. Если счётчиков не видно, сначала выдайте этому аккаунту права просмотра в Метрике.

## Начальные настройки

| pasport-dostupnosty.ru            | 114185674           | /blog/                | Нет       |
| pasport-bezopasnosty.ru           | 112564818           | /blog/                | Нет       |
| boykovgroup.ru                    | 106986222           | Не заданы             | Нет       |
| energo-365.ru                     | 87477971, 113826112 | Не заданы             | Да        |
| elektrolaboratoriya-techotchet.ru | 113216650           | Не заданы             | Нет       |

Новые сайты появляются в селекторе автоматически после добавления источника в «Заявках». Для них администратор указывает счётчики и разделы вручную.

**Важно для Энерго 365:** профиль объединяет основной домен и все его поддомены. Метрика сможет показать только те поддомены, где установлен один из указанных счётчиков. Если на новом поддомене установлен отдельный счётчик, добавьте его номер в этот профиль. Два счётчика на одной странице могут учитывать одни посещения дважды: включайте совместно только счётчики, разделяющие сайты или поддомены. Автоматической дедупликации между разными счётчиками нет.

Разделы статей задаются по одному пути на строку, например `/blog/`. Статьёй считается URL на один уровень глубже: `/blog/nazvanie-stati/`, без страницы списка `/blog/`. Для иной структуры добавьте нужный родительский раздел. Если пути не заданы, просмотры статей показаны прочерком. Заголовки берутся из заголовков страниц Метрики; варианты одного URL суммируются. Адреса в таблицах не содержат параметров запроса и фрагментов.

## Как читать показатели

Посещаемость и источники рассчитывает Метрика, поэтому цифры могут отличаться от встроенной статистики редакции nwdelectricity.ru: у систем разные способы определения визита, фильтрации ботов и блокировщиков. Формат отчёта сохранён, источником посещаемости теперь служит единая система для всех сайтов.

Заявки считаются по дате создания обращения из центральной базы Boykov Services, независимо от статуса и сотрудника. Корзина тоже учитывается: удаление заявки из рабочего списка не стирает факт обращения. Заявки, никогда не поступавшие в сервис, в этот показатель не попадут. История до подключения источника может быть неполной.

Все показатели одного отчёта относятся к **одному интервалу**, указанному над карточками. При использовании сохранённого снимка границы периода тоже сохраняются; заявки пересчитываются для этих границ. Поэтому новая заявка с более поздним временем появится в статистике после следующего полного обновления отчёта. В рабочем разделе «Заявки» она доступна независимо от кэша статистики.

Если доступ к Метрике не настроен или ещё не получен ни один отчёт, посещаемость показана прочерками, а заявки продолжают считаться из центральной базы. При временном сбое сохраняется последний успешный отчёт с прежним интервалом и отметкой времени. Сбой не превращается в нулевые показатели. Метрика может передавать данные с задержкой и использовать выборку; выборка отмечается в интерфейсе. Таблицы показывают наиболее популярные адреса, а суммарные показатели относятся ко всему периоду.

## Реализация и обслуживание

- Новые таблицы SQLite: `statistics_settings`, `statistics_cache`; существующие заявки, документы и аккаунты не изменяются.
- Кэш переживает перезапуск контейнера. Смена счётчиков, путей, режима поддоменов или токена делает прежний снимок неприменимым.
- Одновременные запросы одного отчёта объединяются. Клиент Метрики выполняет не больше двух запросов одновременно, ограничивает время ожидания и делает паузу после отказов и ограничения частоты.
- Используются только фиксированные адреса `https://api-metrika.yandex.net`; токен передаётся в заголовке, перенаправления запрещены. Внешние URL из настроек не принимаются.
- GET `/api/statistics/sites` и `/api/statistics/report?site=ID&period=24h|7|30|90` доступны авторизованным пользователям.
- GET `/api/statistics/counters`, POST `/api/statistics/connection` и PATCH `/api/statistics/sites/:id` доступны только администратору.
- Ответы приватные, `Cache-Control: private, no-store`. Фоновое серверное задание и установка дополнительного кода на сайты не нужны.

## Установка на VPS

После локальной установки патча, успешной проверки, коммита и push:

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-statistics.sh
```

Скрипт требует чистые отслеживаемые файлы. Он сохраняет предыдущий образ приложения, делает согласованную копию SQLite через `VACUUM INTO`, проверяет целостность копии, сохраняет файл подключения при его наличии, затем пересобирает и перезапускает только `app` с ожиданием healthcheck. Контейнер документов не перезапускается. В конце проверяются новые таблицы, `/healthz` и закрытость статистики без входа.

Ожидается `STATISTICS_DEPLOY=OK`; адрес резервной копии выводится как `BACKUP=...`. Если проверка после запуска не прошла, можно выполнить `bash ПУТЬ_ИЗ_BACKUP/rollback-app.sh`: восстановится предыдущий образ с текущими данными. Скрипт отката не подменяет рабочую базу старой копией и не удаляет новые заявки. Копия БД расположена в постоянном томе; точный путь записан в `database-backup.json` внутри каталога BACKUP.

Проверки разработки: `npm run check`, отдельно `node --test tests/statistics.test.js`. API Метрики покрыт воспроизводимой фикстурой; реальная доступность счётчиков проверяется при подключении токена в рабочем сервисе.
