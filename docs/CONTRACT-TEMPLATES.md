# Библиотека шаблонов договоров

Откройте «Договоры → Шаблоны». Все шесть имеющихся типов договора сохраняют
свои поля, расчёты, нумерацию, приложения и исходный макрос. У договора
с согласованием добавлена отсутствовавшая в исходнике кнопка запуска:
используется уже существующий общий макрос ReplaceTags.

## Работа с шаблонами

- Личные аккаунты отдела продаж и администратора могут редактировать,
  загружать, публиковать и восстанавливать версии. Общий доступ позволяет
  скачивать и просматривать историю. Автор и время публикации фиксируются
  на сервере по личной сессии.
- Редактор работает с текстовыми абзацами и ячейками существующего Word
  документа, включая обычный текст колонтитулов. Оформление, таблицы,
  изображения, нумерация и отношения частей файла не пересоздаются.
  Изменённый текст наследует форматирование в месте правки.
  Сложные абзацы с разрывами, объектами, полями Word и гиперссылками
  редактируются в Word, не через текстовый редактор. Это не аналог Word
  с полной разбивкой на страницы.
- Для новой версии скачайте «DOCX для правок», измените его в Word или
  загрузите свой DOCX. Система автоматически добавит соответствующую
  защищённую таблицу автозамен, имеющийся VBA-проект и кнопку запуска.
  DOCM также принимается, если активные компоненты совпадают с исходным
  проверенным макросом. Сторонние макросы, OLE-вложения и внешние
  подключаемые шаблоны не принимаются.
- Поля `autozamena_XXX` имеют разные значения для разных типов договора.
  Для нового файла сохраните поля из предыдущей версии либо выделяйте
  текст абзаца и вставляйте нужное поле из списка. Программа не угадывает
  юридический смысл произвольного текста. Обязательные поля проверяются
  перед публикацией. Для разовых услуг Спецэнергоразвития также проверяется
  структура существующего приложения №1 (7 колонок, 9 заполняемых строк).
- Загрузка создаёт личный черновик, а не заменяет активную версию.
  Кнопка «Опубликовать» проверяет и атомарно сохраняет новую версию.
  С этого момента все новые договоры используют её. Задание, уже принятое
  в очередь, привязано к версии на момент запуска; повторы того же задания
  не выдают новый номер. В результате генерации сохраняются номер версии
  и SHA-256 её исходного файла.
- В истории можно скачать любую редакцию и восстановить её как новую
  активную версию. При одновременной правке другим сотрудником публикация
  устаревшего черновика блокируется. Предыдущая редакция не перезаписывается.

## Хранилище

`/app/data/contracts/template-library.sqlite` в существующем Docker volume
`platform-data` содержит версии DOCM, метаданные, личные черновики и указатели
активных версий. Исходные файлы из репозитория используются **только один раз**
при первом переносе. Схема полей и доверенный макрос далее читаются из
нулевой истории (версии v1), а не из нового образа. Если проверка целостности
не проходит, сервис не подставляет старый шаблон из Git.

Лимиты: 20 МБ на DOCX/DOCM, до 128 МБ после распаковки, 4000 текстовых
блоков, 256 МБ содержимого версий и черновиков в библиотеке. При нехватке
места новая запись блокируется; опубликованная история не удаляется.
Word-файлы закрыты авторизацией, VBA на сервере не исполняется.
Не удаляйте Docker volume (`docker compose down -v` удалит данные).

## Деплой

На VPS Boykov Services, после применения патча, коммита и push:

```bash
cd /opt/boykov-services
git pull --ff-only origin main && bash scripts/deploy-contract-templates.sh
```

Скрипт копирует текущие шесть Word-файлов и SQLite вне Docker volume,
останавливается, если при первом переносе живые шаблоны отличаются от Git,
и сохраняет текущие образы. Перед переключением он закрывает приём новых
заданий, ждёт завершения очереди, создаёт повторную резервную копию,
обновляет оба контейнера и проверяет целостность и авторизацию.
Дождитесь `TEMPLATE_DEPLOY=OK`. На первом запуске будет шесть версий v1.
Не запускайте откат к версии сервиса без библиотеки после публикации
новых шаблонов без отдельного плана переноса данных.

Резервная копия по требованию (сохраняется в /root, закрыта правами доступа):

```bash
cd /opt/boykov-services
bash scripts/backup-contract-templates.sh
```

Копируйте архивы в самостоятельное защищённое хранилище. В архиве также
есть данные существующих задач, не публикуйте его в Git и не отправляйте
посторонним.

Первый тест после подключения: скачать один активный DOCM, подготовить
пробный договор и открыть в Microsoft Word с действующими корпоративными
настройками безопасности. Затем внести небольшую текстовую правку,
опубликовать, создать новый договор и проверить номер версии и текст.
Работу VBA именно в настольном Word проверяет сотрудник; серверные тесты
проверяют структуру OOXML, компоненты и их контрольные суммы, не исполняя VBA.
