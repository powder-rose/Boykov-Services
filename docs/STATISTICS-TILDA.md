# Статистика сайтов Tilda

Поддерживаемые источники: `boykovgroup.ru`, `elektrolaboratoriya-techotchet.ru` и их варианты `www`. Публичный API Tilda предназначен для экспорта страниц и не содержит документированного метода выгрузки посещаемости, поэтому используется отдельный собственный счётчик. Это не экспорт прежней статистики Tilda: учёт начинается с первого принятого просмотра. Существующие webhook заявок, keys и встроенная статистика Tilda сохраняются.

## Установка

1. Применить патч в локальном проекте Boykov Services, выполнить `npm run check`, закоммитить и отправить в `main`.
2. На VPS Boykov Services выполнить `git pull --ff-only origin main`, затем `bash scripts/deploy-tilda-statistics.sh`. Скрипт сохраняет предыдущий образ приложения и онлайн-копию SQLite, обновляет только app и проверяет его здоровье. Дождаться `TILDA_STATISTICS_DEPLOY=OK`.
3. В Tilda для каждого из двух проектов открыть «Настройки сайта → Ещё → HTML-код для вставки внутрь head». Добавить этот фрагмент после существующего кода, сохранив прежние счётчики:

```html
<script src="https://boykov-services.ru/hooks/tilda-statistics/counter.js" defer></script>
```

Если на сайте есть баннер выбора аналитических cookies, подключите скрипт через его механизм согласия. Для собственного внешнего скрипта Tilda документирует такой формат:

```html
<script data-src="https://boykov-services.ru/hooks/tilda-statistics/counter.js" data-tilda-cookie-type="custom"></script>
```

Используйте один вариант, не оба. При наличии механизма согласия счётчик должен запускаться только после разрешения аналитики. Проверьте это при публикации; при использовании другой системы согласия загрузку скрипта нужно связать с её разрешением аналитики. Учитывайте применение локального хранилища в действующем описании счётчиков сайта. [Инструкция Tilda по cookies](https://help-ru.tilda.cc/cookies-consent).

4. Сохранить настройки и нажать «Опубликовать все страницы» в каждом проекте. Открыть оба сайта в обычном приватном окне, разрешив аналитику, если появляется соответствующий выбор. После завершения минуты в Boykov Services открыть «Статистика → Отчёт по сайту → 24 часа». При двух сайтах нельзя считать установку успешной только по одному из них.
5. На VPS проверить `bash scripts/check-tilda-statistics.sh`. После первого принятого события в таблице появляется источник, дата начала учёта, время последнего просмотра и число просмотров за последние 24 часа. `NO_EVENTS` означает, что сервер ещё не получил посещение, а не нулевую посещаемость. Новые ключи и задачи CronTab не нужны.

## Правила учёта

- Сеанс — случайный псевдоним в локальном хранилище сайта с 30 минутами бездействия. Домен каждого сайта считается отдельно; переход между `www` и основным доменом может начать новый сеанс из-за изоляции хранилища браузера. Не размещайте одновременно два экземпляра счётчика на странице.
- Просмотр регистрируется, когда страница видима. Повторная загрузка — самостоятельный просмотр; повторная доставка того же события не увеличивает метрики. Клиент повторяет временно неподтверждённые отправки до 24 часов, максимум 40 ожидающих событий. Сервер использует время первого получения события, поэтому задержанная доставка относится ко времени получения. Если браузер закрыт, повторы возможны при новом посещении.
- Источники: `utm_source`, домен перехода, прямой или внутренний переход. Полный URL с query, содержимое форм, пароли, cookie посетителей и необработанные IP в событие не входят. Сеансовый идентификатор сохраняется на сервере хешированным; сырые данные хранятся до 93 дней и очищаются при первом событии нового дня, сессии — до суток. Серверные журналы Nginx имеют свою политику хранения.
- Блокировщики, недоступность JavaScript, DNT/GPC, отсутствие согласия и распознаваемые роботы влияют на полноту измерений. Метрика визитов не равна числу уникальных физических лиц. Отдельного достоверного типа «статья» в этом счётчике нет, поэтому соответствующий показатель отображается прочерком.
- История посещаемости до подключения отображается как отсутствие данных. Заявки берутся из уже сохранённых строк центрального сервиса, включая корзину, и могут быть доступны до даты начала учёта.
- Отчёты вычисляются из сохранённых событий за завершённые минуты. Периоды: скользящие 24 часа по часам, 7/30/90 календарных дней по Москве. Отсутствие новых событий само по себе не означает сбой, поэтому показывается реальное время последнего просмотра.

Публичный сборщик находится на отдельном маршруте `/hooks/tilda-statistics/view`, с точным списком разрешённых origin, ограниченным форматом и лимитом 4 КБ. Ключ API заявок не используется в браузере. Публичные счётчики не могут гарантировать, что каждое принятое событие относится к человеку; ограничение на 300 новых событий в минуту и 10 000 в сутки на сайт защищает ёмкость SQLite. При превышении сервер возвращает 429 и не подтверждает событие. Дубликаты остаются допустимыми даже при исчерпанном лимите. Отчёты и клиентские данные доступны только после входа в Boykov Services.

Откат установки на Tilda: удалите только добавленный тег и переопубликуйте затронутые страницы. Сведения о заявках и ранее принятые просмотры при этом остаются в базе. Скрипт `rollback-app.sh` из резервной копии VPS нужен только при проблеме самой центральной версии.
