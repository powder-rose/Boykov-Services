# Техотдел в Boykov-services: Google Apps Script → HTTPS-сервер

Эта версия **заменяет необходимость в Google Cloud, Google Sheets API и JSON-ключе сервисного аккаунта** для модуля «Техотдел». Ваши исходные таблицы остаются в Google. Google Apps Script под обычным Google-аккаунтом, у которого уже есть доступ к обеим таблицам, передаёт их содержимое в Boykov-services. Обратной записи в Google нет.

## Что переносим

Рабочий источник «ДОП.РАБОТЫ», файл ID `1-1F68x3sE3uxknDMJEGlc6YtuJ9YgsDRqJutofJdoL4`:

1. `СЭР ТО МСК РЕГИОНЫ` (gid `723255987`)
2. `ДОПЫ` (`0`)
3. `Электрики` (`878613942`)
4. `ЭЛ.ЗАПАС` (`1298694826`)
5. `КАЛЦРУ РОССИЯ` (`2075067225`)
6. `КАЛЦРУ ДОПЫ СПБ` (`1299045180`)
7. `КАЛЦРУ ДОПЫ МСК` (`846887197`)

Эталон бухгалтерии — **только** лист `П/О СЭР ТО` файла `19ls1mrxtFD9gb18MZm8aTR_BEAA-LXulZfrUEZWL02E`. В основной вкладке он определяет 10 защищённых полей: комментарии Ирины (G), код (B), город (P), объект (Q), адрес (R), компания (C), почта (X), телефон (Z), периодичность (W), стоимость (U). Сопоставление — по коду объекта (например, D240), но не по номеру строки. Другие бухгалтерские листы не передаются.

Заметки с именем пользователя и технические правки хранятся локально в SQLite и переживают повторный импорт. При отсутствии/дублировании кода бухгалтерские данные не связываются автоматически.

## 1. Обновите проект локально

Сохраните резервную копию проекта, распакуйте этот архив отдельно и откройте PowerShell в папке архива:

```powershell
node .\apply-push-update.mjs "C:\Users\user\WebstormProjects\boykov-services"
```

Установщик отказывается выполнять обновление при несовпадении проверенных версий файлов, **не** затрагивает `.env`, SQLite, пользователей, историю и сервис документов. Существующий Apps Script ФНС также не меняется.

Затем:

```powershell
cd "C:\Users\user\WebstormProjects\boykov-services"
npm run check
npm run dev
```

При отсутствии данных Google в интерфейсе пока будут нули. Это ожидаемо.

## 2. Секрет передачи на сервере

На **своём** компьютере с Node.js сгенерируйте секрет:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте сгенерированную строку (64 шестнадцатеричных символа) в `.env` **Boykov-services**:

```dotenv
TECH_PUSH_IMPORT_TOKEN=СЕКРЕТ_ИЗ_КОМАНДЫ
```

Строки `GOOGLE_SERVICE_ACCOUNT_FILE` и `GOOGLE_SERVICE_ACCOUNT_JSON` **не нужны**, удалите их, если раньше добавляли для техотдела. Оставьте старые `AUTH_PASSWORD_HASH`, `WORKER_TOKEN`, `YANDEX_*` и прочие настройки как были. Файл `.env` не выкладывайте в GitHub.

Перезапустите Node-приложение или контейнер после изменения `.env`.

**Важно:** Apps Script работает на стороне Google и **не может отправлять запросы на `localhost:8787`**. До реальной передачи обновлённый Boykov-services должен быть доступен по вашему рабочему **HTTPS-домену**, с доступным маршрутом `/hooks/technical/import/start`. Не публикуйте чувствительные данные в открытый доступ, не отключайте HTTPS и не добавляйте токен в URL.

## 3. Деплой на рабочий сервер

После успешного `npm run check` закоммитьте проверенный код под своим GitHub-аккаунтом и обновите обычным процессом Boykov-services на VPS. При использовании Docker Compose (из корня проекта на сервере):

```bash
docker compose up -d --build app
docker compose ps
```

Старый worker документов можно не пересобирать, если его код не менялся. Проверьте `/healthz` на HTTPS и вход в `#technical`. Не забывайте задать **тот же** `TECH_PUSH_IMPORT_TOKEN` в `.env` на VPS. Для импорта не нужен путь к JSON-ключу.

## 4. Установите Google Apps Script без Google Cloud

1. Откройте бухгалтерскую таблицу `КОНТРАГЕНТЫ` → **Расширения → Apps Script**.
2. **Не заменяйте существующий `Код.gs`**: там функции ФНС и другая рабочая автоматизация. Создайте **новый файл скрипта** `BoykovTechnicalPush.gs` и вставьте полностью содержимое файла из папки `apps-script/` этого архива.
3. В Apps Script откройте **Настройки проекта → Свойства скрипта (Script properties)**. Добавьте:

   - `BOYKOV_TECH_SERVER_URL` = `https://ВАШ_РАБОЧИЙ_ДОМЕН` (без завершающего `/` и **без** `/hooks`)
   - `BOYKOV_TECH_PUSH_TOKEN` = **та же** строка, что в `TECH_PUSH_IMPORT_TOKEN` на VPS

   Секреты не добавляйте в исходный код, скриншоты и логи.
4. Убедитесь, что Google-аккаунт, от которого создаются триггеры, имеет доступ **на чтение обеих** таблиц: `КОНТРАГЕНТЫ` и `ДОП.РАБОТЫ`.
5. Сохраните файл. Выберите сверху `setupBoykovTechPush` → **Выполнить**. При первом запуске Google запросит разрешения на доступ к таблицам и внешние HTTPS-запросы. Устанавливаются только собственные триггеры `boykovTech*`, существующие триггеры ФНС не удаляются.
6. Выберите `boykovTechPushNow` → **Выполнить**. Это **первая полная передача** восьми источников (семь рабочих вкладок плюс один бухгалтерский лист). Дождитесь завершения. В журнале должно появиться `BOYKOV_TECH_IMPORT_OK`.

После начальной передачи:

- Ручное редактирование одного из восьми листов отправляет **изменённые строки** на сервер через `boykovTechOnEdit`.
- Изменение структуры листа запускает полную отправку через `boykovTechOnChange`.
- Каждые **15 минут** `boykovTechScheduledSync` выполняет контрольный полный импорт, в том числе изменений от формул или других скриптов, которые не вызывают `onEdit`.

Это **быстрая, но не строго мгновенная** синхронизация. Задержка зависит от выполнения Google Apps Script и доступа к серверу. Не создавайте второй такой же набор триггеров в другом Apps Script-проекте.

## 5. Проверка

1. Откройте раздел `Техотдел` и убедитесь, что у семи вкладок появились реальные счётчики строк.
2. Найдите `D240` в `СЭР ТО МСК РЕГИОНЫ`. Убедитесь, что стоимость соответствует **бухгалтерской** таблице (при предыдущей сверке она составляла 2200 вместо старых 1700 в «ДОП.РАБОТЫ»).
3. Измените тестовое значение в бухгалтерии и проверьте его появление в Boykov-services, не меняя исходные технические заметки.
4. Авторизуйтесь под личной учётной записью сотрудника техотдела, добавьте заметку. В карточке должны появиться автор и дата.
5. Измените рабочее поле, затем вручную выполните `boykovTechPushNow`: оно должно сохраниться.
6. Убедитесь, что бухгалтерские поля не редактируются из интерфейса и API Boykov-services.

## Диагностика

- `HTTP 403` на `/hooks/technical/import/...`: отличаются `TECH_PUSH_IMPORT_TOKEN` и `BOYKOV_TECH_PUSH_TOKEN`. Не пересылайте токены в чат.
- `HTTP 404`: на рабочем сервере ещё нет новой версии модуля или маршрут не проксируется веб-сервером.
- `HTTP 409` при изменении ячейки: первый полный импорт не выполнен, либо запущен параллельно. Выполните `boykovTechPushNow`, очередная полная сверка также исправит расхождение.
- `Не удалось открыть таблицу`: аккаунту, под которым установлены Apps Script-триггеры, нужен доступ к обеим таблицам.
- Если скрипт начал полную передачу, но она оборвалась, **последние успешные данные остаются в SQLite**. В Apps Script можно повторить `boykovTechPushNow`.
- Если таблица сильно сократилась по количеству строк, сервер остановит импорт и сохранит предыдущие данные до проверки причины.
- Историю технических полей и заметок не удаляйте из SQLite. Делайте резервную копию Docker volume с `platform.sqlite`.

## Ограничения

- Apps Script имеет квоты на время выполнения, триггеры и HTTPS-запросы. Для чрезвычайно крупных таблиц может потребоваться более редкая полная сверка или настройка отправки только изменённых листов.
- Исходные таблицы не меняются ни при импорте, ни при сохранении технических комментариев. Обратная синхронизация сознательно отсутствует.
- Сложные форматирования Google (рисунки, фильтры, объединённые ячейки) не переносятся в сервис; данные, структура семи вкладок и редактируемые технические поля сохраняются.
- Перемещение строк с нестабильными идентификаторами и изменение кода объекта в источнике может изменить привязку истории. В таких случаях проверяйте сопоставление.
- **Ни Google Cloud Billing, ни сервисный аккаунт Google, ни JSON-ключ для этой схемы не нужны.**
