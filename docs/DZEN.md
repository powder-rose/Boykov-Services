# Комментарии Дзена · Zenbot

Модуль переносит в Boykov Services только обработку комментариев из прежнего Zenbot. Он не переносит Telegram-бота, генерацию статей или другие задачи. Рабочая очередь, история, шаблон промпта и настройки сохраняются в существующей SQLite-базе приложения; перезапуск и пересборка приложения их не удаляют.

## Режимы

- **Пауза** — режим после первой установки. Можно добавить комментарий вручную, запросить сбор и подготовить черновик. Новые публикации не разрешаются.
- **С проверкой** — агент собирает комментарии, ИИ готовит черновики, сотрудник проверяет/редактирует каждый текст и подтверждает отправку.
- **Автоответы** — дополнительно разрешает автоматическую отправку подходящих ответов в пределах настроенного лимита. Доступно только после подключения агента и ИИ, подтверждения фильтра «Без ответа», заполнения видимых имён своего канала и явного согласия администратора. Ссылки в автоматически подготовленных ответах требуют ручной проверки.

По умолчанию: сбор раз в 10 минут, до 5 новых черновиков за цикл, до 10 попыток отправки в сутки по Москве, максимум 700 символов ответа. Ограничение считается по разрешённым попыткам, включая неподтверждённые: это защищает от повторных отправок при сбоях. Пауза останавливает новые отправки; уже начатая публикация может завершиться.

Личный аккаунт сотрудника позволяет работать с комментариями, общий доступ — просматривать данные. Администратор управляет режимом, промптом и лимитами. В журнале отражаются инициатор действий и версия промпта. Тест промпта отправляет только введённый пример в YandexGPT, ничего не сохраняет как комментарий и не публикует. Для возврата к прежнему промпту можно загрузить его текст из истории и сохранить как новую версию.

## 1. Настроить сервер

После доставки изменений в `main`, на VPS Boykov Services:

```bash
cd /opt/boykov-services
git pull --ff-only origin main
python3 scripts/configure-dzen.py
bash scripts/deploy-dzen.sh
```

Скрипт настройки создаёт приватный `.env.dzen` с отдельным ключом подключения агента и двумя ключами YandexGPT. Если сохранился старый env Zenbot, вместо обычной команды настройки можно выполнить:

```bash
python3 scripts/configure-dzen.py --legacy-env /полный/путь/к/сохранённому.env
```

Из прежнего файла читаются только `YC_FOLDER_ID` и `YC_API_KEY`. Telegram-токен, сессии и другие параметры не нужны. Если был только ключ сервисного аккаунта в отдельном файле, требуется действующий API-ключ Yandex Cloud. Если ключей пока нет, оставьте оба поля пустыми: ручная работа доступна сразу. Не отправляйте ключи, файлы env и браузерный профиль в чат и не добавляйте их в Git. Сохраните показанный ключ агента в защищённом месте для следующего шага.

Скрипт деплоя создаёт проверенную резервную копию базы, собирает только `app` и проверяет приватность маршрутов, схему и здоровье сервиса. При неудаче возвращает предыдущий образ приложения; базы и тома не удаляет. Признак успеха: `DZEN_DEPLOY=OK`.

## 2. Подключить Студию Дзена

Прежний Zenbot работал через авторизованный браузер. Здесь браузерный агент вынесен отдельно: так на VPS с 1 ГБ RAM не нужно запускать Chromium. Промпт и управление при этом остаются на сайте Boykov Services. На Windows с Python 3.12 из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Install-Agent.ps1
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Start-Agent.ps1 -Mode configure
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Start-Agent.ps1 -Mode login
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Start-Agent.ps1 -Mode run
```

Перед настройкой откройте в своём браузере комментарии именно нужного канала в Студии, выберите фильтр «Неотвеченные» и скопируйте адрес. Текущая Студия использует `answer=notReply`; прежний Zenbot использовал `comments_data=n_reply`. Введите этот адрес и ключ агента в терминале. В режиме `login` откроется новый браузер: войдите вручную в свою учётную запись, откройте комментарии и нажмите Enter в терминале. Данные авторизации остаются в локальном отдельном профиле. Затем запустите `run`.

Если коннектор был настроен до обновления фильтра и сохранил адрес без параметров, после обновления приложения и агента достаточно остановить прежний процесс и вновь выполнить `run`. При запуске агент добавит актуальный фильтр к адресу того же канала. Ключ, профиль, ID агента и база комментариев сохраняются. При изменении фильтра сервер сбрасывает прежнюю проверку и приостанавливает отправку; новый сбор должен подтвердить фильтр по адресу открытой страницы и видимому активному элементу интерфейса. Не меняйте конфигурацию вручную и не сбрасывайте базу.

Агент должен постоянно работать на авторизованном компьютере. При выключении компьютера или закрытии процесса новые комментарии не собираются, но уже принятые данные не теряются. Для круглосуточного режима позднее можно установить тот же агент на отдельную постоянно работающую машину. Используйте автоматизацию только в рамках разрешений и правил Дзена.

## 3. Проверить перед включением автоматических ответов

1. В разделе «Комментарии Дзена» оставьте режим «Пауза» и нажмите «Собрать комментарии».
2. Дождитесь `DZEN_SCAN=OK COUNT=... VERIFIED_FILTER=1 BOUND=... READY=...` в терминале агента и появления ленты. `BOUND` — число комментариев с установленной привязкой, `READY` — число потенциально доступных для отправки в текущем сборе (окончательное решение зависит от состояния очереди). Сверьте канал, автора, статью и текст с видимыми данными Студии. Сбор ограничен 250 видимыми комментариями, 18 прокрутками и безопасным размером отчёта; это не полный экспорт архива Дзена.
   Если Студия скрывает настоящий ID, агент использует видимые ссылки публикации и профиля автора, полный текст и данные родительских комментариев. Меняющаяся подпись времени публикации не является частью названия и не влияет на привязку. По умолчанию контекстная привязка требует подтверждения сотрудника; для строго проверенной привязки `context_ui_` администратор может отдельно разрешить автоответы. При отправке агент вновь проверяет фильтр, единственность совпадения в загруженной ленте и конкретный DOM-элемент; при неоднозначности или наличии видимого ответа автора канала в ветке отправка прекращается. Учитываются только действительно показанные элементы Студии. Если привязка не подтверждена, ответ можно подготовить и скопировать вручную.
   При первом сборе после обновления старые записи без ID сопоставляются с точными уникальными совпадениями; сохранённые черновики, история и статусы не удаляются. В ссылке автора Дзен может показывать его имя вместе с пометкой «подписчик»/«автор» и относительным временем комментария. Агент исключает эти служебные подписи, но по-прежнему сверяет имя с обращением, которое Дзен подставил в форму ответа. Существующие контекстные карточки обновляются только при совпадении ID привязки, текста и публикации. Неоднозначные старые записи остаются без разрешения на отправку. Не сбрасывайте базу и не переавторизуйтесь без необходимости.
3. В настройках укажите точное отображаемое имя собственного канала и проверьте промпт на примере. Переключитесь на «С проверкой».
4. Подготовьте один реальный черновик, внимательно проверьте его, затем подтвердите отправку, только если действительно хотите опубликовать его. Проверьте текст в Студии и отметку «Отвечено» в сервисе. После этого можно решить, нужен ли автоматический режим.

Интерфейс Студии меняется со временем. Коннектор основан на селекторах прежнего Zenbot, но реальная авторизованная сессия и публикация должны быть проверены после подключения. После отправки агент проверяет появление точного текста ответа с пометкой автора канала в исходной ветке. Если фильтр «Неотвеченные» скрыл карточку, агент открывает ту же страницу комментариев без фильтра, находит исходную публикацию и ветку, при необходимости раскрывает ответы обычным элементом интерфейса, и проверяет опубликованный свежий ответ. Эта дополнительная проверка ничего не публикует и не повторяет нажатие отправки. При изменении интерфейса, требовании повторного входа или ограничении доступа агент останавливается. При неопределённом результате отправки комментарий получает статус «Проверить», автоматизация приостанавливается и не повторяет отправку. Вручную проверьте исходную ветку, затем либо подтвердите публикацию, либо верните черновик. Не запускайте повторную отправку до проверки.

## Подтверждение непосредственно под статьёй

Если опубликованный ответ исчезает из фильтра «Неотвеченные» и не виден в полном списке Студии, агент может проверить исходную публичную публикацию. Однократно укажите подтверждённую ссылку собственного канала (пример для канала `/specons`), предварительно остановив старый агент:

```powershell
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Start-Agent.ps1 -Mode public-author -PublicAuthorUrl https://dzen.ru/specons
powershell -ExecutionPolicy Bypass -File .\integrations\dzen\Start-Agent.ps1 -Mode run
```

Настройка сохраняет существующий ключ, профиль браузера и ID агента. Она не требует повторной авторизации и пересборки VPS. Агент открывает только исходную статью, проверяет точное совпадение профиля и текста исходного комментария, ветки, ссылки собственного канала, полного отправленного текста (включая обращение) и свежести ответа. При необходимости раскрывает ответы обычным элементом интерфейса. Если совпадение подтверждено, выводит `DZEN_CONFIRM=PUBLIC_ARTICLE` и `DZEN_PUBLISH=sent`. При отсутствии доказательства, неоднозначности, ограничении доступа или таймауте отправка остаётся неподтверждённой; повторной публикации не происходит. Уже опубликованные ответы со статусом «Проверить» нужно вручную отметить опубликованными, а не отправлять заново.

Длинные комментарии на публичной странице могут быть свёрнуты под «ещё». Агент использует совпадение видимой части текста и профиля только для раскрытия нужной карточки; подтверждение возможно исключительно после точного сравнения полного видимого текста. Скрытые модерацией комментарии не раскрываются. В Студии (в том числе под видео) ответ может отображаться без пометки «автор»: тогда проверяется точная ссылка настроенного профиля канала и видимое время публикации. При отсутствии подтверждения `DZEN_CONFIRM_DETAIL=...` показывает этап проверки, на котором совпадение отсутствовало. Ни одна из этих проверок не выполняет повторную отправку.

## Черновики и обновление старых привязок

Фильтр «Можно отправить» показывает только черновики, подтверждённые актуальным сбором неотвеченных комментариев. «Без подтверждения» сохраняет черновики, для которых Дзен пока не показал однозначно связанную карточку. Если исходный комментарий вновь появится в очередном сборе, его привязка обновится. Глубина обычной прокрутки списка увеличена; агент ждёт подгрузки новых комментариев, пока список движется, в пределах установленного лимита в 250 карточек. Старые карточки, которых нет в списке неотвеченных, не разблокируются вручную через базу.

Когда свежий сбор устанавливает однозначную связь прежней карточки без ID с уже существующей карточкой, в рабочем списке остаётся только подтверждённая карточка. Её существующий ответ не перезаписывается. Если она ещё не содержит ответа, используется сохранённый старый черновик. Прежняя карточка, её ответ и история доступны во вкладке «Архив дублей»; отправка и генерация из архива недоступны. Неоднозначные совпадения, ранее подтверждённые публикации и комментарии с неопределённым результатом отправки не архивируются автоматически. Фоновая генерация не создаёт новые черновики для неподтверждённых комментариев.

## Автоматическая очередь

После обновления сервера и локального агента оставьте модуль на паузе, запустите агент, запросите сбор и дождитесь подтверждения фильтра. В настройках выберите «Автоответы» и включите «Автоответы по точной привязке». Поддержка этой настройки появляется только у обновлённого агента с указанным публичным профилем автора канала. Старый тип `context_` без подтверждённой структуры ветки не допускается к автоотправке. Существующая ручная очередь остаётся доступной.

Чтобы автоматически обработать уже подготовленные черновики, отдельно включите «Отправлять готовые черновики ИИ». Подходят только сохранённые результаты генерации текущего промпта без последующих изменений сотрудником, ссылок, ошибок, отмены или предыдущей начатой публикации. Перед каждой отправкой сервер повторно проверяет режим, разрешение, дневной лимит и актуальность привязки; агент проверяет точный DOM-элемент и профиль канала. Дневной лимит учитывает уже начатые попытки и не резервирует больше задач, чем позволяет остаток лимита. Настройки требуют явного согласия администратора и отражаются в журнале. При неопределённом результате агент останавливается, как и в ручном режиме.

## Проверки разработки

```bash
npm run check
python -m unittest discover -s integrations/dzen -p 'test_*.py' -v
```

Тесты используют синтетические данные, имитацию YandexGPT и браузерных действий. Они не публикуют комментарии и не используют аккаунт Дзена.
