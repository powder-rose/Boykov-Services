# Клиенты BoykovDocs

Раздел «Клиенты BoykovDocs» хранит контакты пользователей, их данные компании и журнал звонков отдела продаж. Источник — файлы, которые уже сохраняет API BoykovDocs. Почтовый ящик не используется как очередь.

## Какие данные поступают

Карточка определяется неизменным **ID пользователя BoykovDocs**. Компания принадлежит именно этому ID. Одинаковые имена, телефоны, почта и ИНН не объединяют разных пользователей. В карточке рядом с компанией явно показано, кто её заполнил: имя, почта, ID. Сохранённые версии компании содержат снимок контактов того же пользователя.

Контакты: ID, имя, телефон, email и дата регистрации. Компания: название, ИНН, должность и ФИО руководителя, должность и ФИО ответственного по охране труда, дата сохранения по Москве. Новое сохранение обновляет компанию в той же карточке. История звонков остаётся.

Начало загрузки: **19 ноября 2026 года, 00:00 по Москве** (`2026-11-18T21:00:00.000Z`). Дата фиксируется в базе Boykov Services и не меняется при перезапуске или перевыпуске ключа. Старые регистрации и старые профили компаний не загружаются. Если ранее зарегистрированный пользователь сохранит компанию после этой даты, его карточка появится с новыми данными компании и его контактами; исходная дата регистрации останется видимой.

Коннектор раз в 30 секунд читает актуальные `users.json` и `company-profiles.json`, сопоставляет компанию по ключу `profiles[userId]`, сохраняет события в собственную SQLite-очередь и доставляет их с повторами. Перечитывание неизменённых файлов не создаёт новых событий. Подтверждение сервера проверяется по ID события и пользователя; потеря ответа не создаёт дублей. Очередь сохраняется на диске при перезапуске. Непринятые события не выбрасываются. Проблемы чтения, доставки и устаревшая связь отображаются в разделе.

Это сбор текущих сохранённых данных, а не журнал всех действий сайта: несколько изменений компании между опросами могут объединиться в последнее состояние. В истории показываются версии, которые коннектор успел получить. Компания, впервые заполненная до даты начала и с тех пор не изменявшаяся, не импортируется даже вместе с новой карточкой контакта.

## Звонки

Фильтры: все, не звонили, звонили; только с компанией; мои звонки. Поиск по имени, телефону, email, ID и данным компании, включая ИНН. Сортировка по времени регистрации или последнего сохранения компании. Время интерфейса — Москва.

Ссылка на телефон сама не отмечает звонок. Менеджер выбирает «Связались», «Не дозвонились» или «Перезвонить», добавляет комментарий и сохраняет результат. Сервер записывает имя и ID вошедшего сотрудника, время и текущий телефон клиента. Клиент не может подставить имя автора. Повтор сохранения после сетевой ошибки не создаёт второй звонок. При одновременном изменении карточки интерфейс обновляет её и сохраняет черновик комментария для повторного подтверждения.

При общем входе автор — «Общий доступ»; для персональной подписи нужен личный аккаунт. Отменить ошибочную отметку может автор или администратор. Запись, автор и сведения об отмене остаются в истории. После отмены всех действующих отметок карточка снова попадает в «Не звонили». «Звонили» означает наличие отмеченной попытки, в том числе без ответа.

## Установка в локальный проект

Применить архив патча через `Install-Patch.ps1`, пройти `npm run check`, сделать обычный коммит от своего имени и push. Патч не создаёт аккаунтов и не содержит ключей или реальных клиентов.

## Обновление Boykov Services на VPS

На сервере **Boykov Services**, где проект находится в `/opt/boykov-services`:

```bash
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-docs-customers.sh
```

Скрипт требует чистых отслеживаемых файлов, сохраняет согласованный снимок SQLite через `VACUUM INTO`, проверяет его и оставляет старый образ для отката. Затем пересобирает и запускает только `app`, ждёт готовности и проверяет миграции, здоровье API и закрытый доступ. Контейнер документов не перезапускается. Путь `BACKUP` выводится в консоль. Для отката только кода выполнить `bash <BACKUP>/rollback-app.sh`; текущая база остаётся на месте.

Открыть **Клиенты BoykovDocs → Подключение** под администратором и создать ключ. Он показывается один раз. Не отправлять ключ в чат, Git или скриншоты. Перевыпуск ключа отключает прежний коннектор до повторной настройки.

## Подключение сервера BoykovDocs

Выполнить под `root` **на сервере BoykovDocs**, а не на сервере Boykov Services. Можно использовать существующий свежий клон Boykov-Services; либо создать отдельный каталог:

```bash
git clone https://github.com/powder-rose/Boykov-Services.git /opt/boykov-services-connector
cd /opt/boykov-services-connector
bash scripts/install-docs-customers.sh
```

Если этот каталог уже существует, выполнить в нём `git pull --ff-only`, затем установщик. Когда появится скрытый запрос, вставить ключ из Boykov Services и нажать Enter. Ключ не отображается при вводе.

Установщик проверяет доступ, находит хостовый каталог данных через mount контейнера `boykovdocs-api` в `/app/data` и запускает отдельный Compose-проект `boykovdocs-customers-delivery` на Node 24. Он не меняет файлы BoykovDocs, его репозиторий, регистрацию, API, письма, платежи или контейнеры сайта. Сторонний cron не нужен. Права пользователя берутся из контейнера API, чтобы читать закрытые файлы данных.

Монтируется **каталог** данных только для чтения: отдельные bind mount файлов несовместимы с атомарной заменой JSON при сохранении. Пароли, токены, платёжные данные и содержимое почтовой очереди не копируются. Конфигурация с ключом и локальная очередь закрыты правами файлов; исходящие запросы идут по HTTPS с проверкой сертификата, без переходов на другой адрес.

Успешный результат: `DOCS_CUSTOMERS_CONNECTION=OK`. Через минуту проверить зелёное «Доставка работает» и карточки. Если новых пользователей/сохранений с 19 ноября нет, пустой список нормален. Для проверки достаточно зарегистрировать тестового пользователя обычной формой, сохранить ему компанию и проверить, что её ID совпадает с ID карточки.

Диагностика без показа ключей и клиентских данных:

```bash
docker compose -f /opt/boykovdocs-customers-delivery/compose.json ps
docker compose -f /opt/boykovdocs-customers-delivery/compose.json logs --tail 20 delivery
```

Лог содержит только состояние и количество событий. Каталоги `state` и данные Boykov Services необходимо сохранять при обслуживании: в них очередь, принятые карточки и история звонков. При сетевой недоступности восстановить соединение и дать коннектору повторить отправку; не удалять очередь. При переустановке используется та же очередь и дата начала.

Скрипт подключения рассчитывает на подтверждённую структуру BoykovDocs: контейнер `boykovdocs-api`, JSON-массив пользователей и `company-profiles.json` версии 1. Если структура отличается, подключение останавливается и требует проверки; установка кода не означает, что production уже подключён.

## Удаление карточек

В карточке пользователя нажмите «Удалить», проверьте имя, контакт и ID, затем подтвердите «В корзину». Карточка вместе с компанией и звонками исчезнет из рабочего списка, поиска и счётчиков. Кнопка «Корзина» открывает удалённые карточки; в каждой доступно «Восстановить». История звонков и связь с исходным ID сохраняются. Персональная подпись автора удаления берётся из текущего аккаунта; при общем входе указывается «Общий доступ». Действия удаления и восстановления сохраняются в журнале на сервере.

Учётная запись на BoykovDocs продолжает работать: удаление относится к карточке в Boykov Services. Доставка повторных событий и новых сохранений компании обновляет карточку в корзине и не восстанавливает её автоматически. После ручного восстановления видны актуальные данные и прежняя история общения. В корзине нельзя добавлять звонки или отменять прежние отметки.

Удаление и восстановление доступны авторизованным сотрудникам и через общий вход, как в разделе заявок. Если карточку успели изменить, интерфейс предложит проверить обновлённые данные; при сетевом сбое повтор того же запроса не создаёт второе действие. Новая миграция добавляет поля удаления без очистки существующей базы. Для обновления достаточно развернуть только приложение Boykov Services через `scripts/deploy-docs-customers.sh`; коннектор на сервере BoykovDocs не нужно перенастраивать.

## Обновления компаний

Реальное изменение реквизитов создаёт уведомление «Обновлено». Первый сохранённый профиль, повторная доставка, изменение только контактов и неизменившиеся значения компании не создают уведомлений об изменении компании. При запуске новой версии уже сохранённая история проверяется один раз: подтверждённые прежние изменения также отображаются. Неполученные промежуточные версии восстановить невозможно, поскольку коннектор собирает текущее состояние файлов.

Виджет над списком показывает число компаний с непросмотренными изменениями и время последнего обновления по Москве. «Показать обновлённые» включает соответствующий фильтр. В стандартном порядке «Сначала новые» непросмотренные обновления идут первыми, включая первую страницу; внутри группы — самые свежие изменения. Выбор «Сначала ранние» сохраняет явную хронологическую сортировку.

В карточке показаны дата изменения и поля последнего изменения; эти поля выделены в блоке компании. «Просмотрено» подтверждает именно текущую версию компании. У каждого личного аккаунта собственное состояние просмотра: отметка одного сотрудника не скрывает изменения у другого. Общий доступ имеет общее состояние просмотра. Простое открытие карточки не снимает уведомление. Если компания вновь изменится во время просмотра, старая кнопка не скроет новое обновление: данные будут обновлены и потребуется новое подтверждение. После следующего изменения пометка снова становится непросмотренной.

Компания, обновлённая в корзине, остаётся там и не увеличивает счётчик активных изменений. При ручном восстановлении актуальные непросмотренные изменения снова видны. Звонки, их авторы и история сохраняются. Коннектор на сервере BoykovDocs перенастраивать не требуется.

Главные заголовки всех разделов рабочего пространства используют общий декоративный компонент точки с цветом #c77796, как в техотделе. Точка скрыта от экранных дикторов и наследует размер заголовка.
