# Общая статистика сайтов

Раздел «Статистика → Все сайты» дополняет существующий подробный отчёт. По умолчанию выбраны все зарегистрированные сайты и период 7 дней. Нажатие на тег показывает/скрывает сайт; график, общие суммы и таблица меняются сразу. «Показать все» и «Снять выбор» управляют всем набором. Если ничего не выбрано, показывается приглашение выбрать сайты вместо фиктивных нулевых показателей.

## Интерфейс

- Цветной кружок рядом с названием совпадает с цветом линии и обозначением в значениях/таблице. Цвет закрепляется за ID сайта в `statistics_site_colors`, одинаков для всей команды и сохраняется после переименования, добавления сайтов и перезапуска. Назначение индекса выполняется транзакцией. Удаление другого сайта не меняет цвета оставшихся.
- Карточки «Визиты», «Просмотры страниц», «Просмотры статей», «Заявки» показывают суммы выбранных сайтов; клик меняет показатель графика. Показатель можно также выбрать прямо над графиком.
- Периоды: последние 24 часа с часовыми интервалами либо 7/30/90 календарных дней по Москве, включая доступную часть сегодняшнего дня.
- «По дням/часам» показывает значения интервала. «Накопительно» складывает значения с начала отчёта каждого сайта: это рост накопленного количества, не процент изменения к прошлому периоду.
- Наведение или перемещение указателя выбирает интервал и показывает карточку с датой, выбранным показателем, цветами, названиями сайтов и точными числами. Она учитывает выбранные теги и накопительный режим; прочерк обозначает отсутствие данных, ноль остаётся нулём. Клавиши влево/вправо, Home/End работают на фокусированном графике, Escape закрывает карточку. На сенсорном экране интервал выбирается касанием, а в узком блоке карточка располагается под графиком. Исходные границы интервалов доступны в расшифровке под ним.
- В таблице «Сайты в цифрах» видны все четыре показателя, актуальность источника и время его обновления. Название сайта открывает прежний подробный отчёт с передачей выбранного периода. Возврат в общий обзор сохраняет фильтры и режим графика.
- При открытом активном разделе обновление проверяется каждые 30 секунд, при возвращении в видимую вкладку и по кнопке «Обновить». Запросы отменяются при смене периода/экрана; старый ответ не подменяет новый период.

## Подсчёт и полнота

Обзор использует имеющиеся native-отчёты из админок сайтов и регистрацию источников раздела «Заявки». Не обращается к внешним системам аналитики, не устанавливает новые счётчики и не требует повторного подключения работающих каналов. Новые сайты автоматически появляются в списке; посещаемость доступна после подключения источника статистики. Этот патч не заменяет задачу установки отсутствующих источников.

Каждый KPI показывает, для скольких выбранных сайтов есть данные. Прочерк — отсутствие значения; реальный измеренный ноль остаётся нулём. Неизвестные точки не заполняются нулями и не соединяются через пропуск. Сайт без native-отчёта может показывать заявки, уже полученные в Boykov Services, включая корзину, как в прежнем отчёте. Если native-отчёт есть, заявки берутся только из него: копии заявок в центральной базе повторно не прибавляются.

Устаревшие отчёты и ошибочные источники исключаются из общих сумм и графика с явным предупреждением. Подробный отчёт сохраняет прежнее поведение: последний снимок можно просмотреть с отметкой устаревания. Срок актуальности соответствует существующей логике — 3 минуты; смена московского календарного окна также делает старый дневной отчёт неактуальным. Ошибка одного сохранённого источника изолируется, остальные продолжают отображаться.

Native-сайты передают срезы в разное время. Их исходные значения и интервалы не интерполируются и не пересчитываются пропорционально минутам. Ось объединяет фактические часовые/дневные корзины по времени Москвы. Крайние точки могут быть неполными; точные границы показаны в расшифровке, а время обновления — в таблице. Поэтому общая временная рамка rolling 24h может быть шире ровно 24 часов на разницу свежих срезов, а в часовом графике возможны 25–26 корзин. Каждый сайт при этом отражает собственный полученный 24-часовой отчёт; суммы соответствуют его фактическим точкам. На границе суток старые календарные окна не смешиваются с новыми.

Суммируются визиты сайтов, а не уникальные люди между разными доменами. Сравнение с предыдущим периодом в процентах не вычисляется: текущий протокол хранит последние срезы, которых для такого сравнения недостаточно. В накопительном режиме пробелы остаются пробелами, а сумма растёт по реально доступным точкам.

## Доступ и установка

Новый `GET /api/statistics/overview?period=...` использует существующий вход в рабочее пространство и `private, no-store`. Ключи подключений не включаются в ответ. Роли и аудитория раздела не меняются; установленные коннекторы, данные заявок, native-отчёты и остальные модули сохраняются. Добавляется только таблица закреплённых цветов.

Применить архивный патч PowerShell-установщиком в корне локального проекта. База — main `16063d3` или совместимая версия. Установщик проверяет применимость и уже установленный патч, сохраняет копии затронутых файлов внутри `.git/boykov-patch-backups`, запускает `npm run check`. Коммитов и push не делает.

После успешной проверки выполнить коммит/push обычным способом, затем на VPS Boykov Services:

```bash
cd /opt/boykov-services
git pull --ff-only
bash scripts/deploy-statistics-overview.sh
```

Скрипт сохраняет согласованный снимок SQLite через `VACUUM INTO` с проверкой целостности, предыдущий образ и команду отката; обновляет только `app`, проверяет healthy, миграцию и закрытость API. Ожидается `STATISTICS_OVERVIEW_DEPLOY=OK`. Сервисы документов и коннекторы не перезапускаются; дополнительных cron, ключей и библиотек нет.

Путь резервной копии выводится как `BACKUP=...`; откат приложения — `bash <BACKUP>/rollback-app.sh`. Таблица цветов совместима со старым приложением. Не заменять всю базу автоматически при откате: после снимка могли поступить новые заявки и другие данные.

## Проверки

`npm run check`: TypeScript/Vite и весь набор тестов. Девять новых проверок охватывают авторизацию, приватность, совпадение сумм с реальными интервалами, отсутствие двойного счёта заявок, разное время срезов и разрывы, nullable/нулевые метрики, stale/error, переход московских суток, постоянство цветов и расчёт выбранного набора. В браузере проверяются теги, режимы/показатели, клавиатура, пустой выбор, переход и возврат из подробного отчёта. `bash -n` проверяет синтаксис скрипта деплоя. Производственный запуск выполняется пользователем после push.
