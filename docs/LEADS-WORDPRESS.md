# Подключение дополнительных сайтов

Патч добавляет исходники WordPress-коннектора и проверки. Работающий
Boykov Services уже позволяет создавать сайты через интерфейс;
ради этих подключений пересобирать его контейнеры не требуется.

## Электролаборатория — формы Tilda

Главная `https://elektrolaboratoriya-techotchet.ru/` использует восемь форм
Tilda, включая квизы. Для настройки нужен доступ к исходному проекту Tilda.

1. В Boykov Services → Заявки → Добавить сайт указать название, домен
   `elektrolaboratoriya-techotchet.ru`, способ **Webhook Tilda**.
2. Скопировать выданные URL и ключ нового сайта.
3. В Tilda → Настройки этого проекта → Формы → Webhook: URL из центра,
   API METHOD `HEADER`, API NAME `Authorization`, API KEY — значение целиком
   с `Bearer` и пробелом. Существующие приёмщики сохранить.
4. Назначить сервис всем формам и опубликовать страницы. Если проект
   экспортируется на отдельный хостинг, обновить и опубликованную копию.
5. Проверить все восемь форм: консультацию и отдельные квизы. Сопоставить
   ответы квиза и контакты с карточками в Boykov Services.

Подробности и ограничения повторов: [TILDA.md](TILDA.md).

## Энерго 365 и все поддомены WordPress Multisite

Версия плагина 1.1.0 принимает формы Contact Form 7 с `energo-365.ru` и всех
его поддоменов, включая `lp.energo-365.ru` и вложенные поддомены. В центре
используется один источник «Энерго 365». В каждой карточке сохраняются
поле «Сайт», исходный адрес страницы и название формы.

На публичных главных основного сайта и `lp` проверены формы Contact Form 7
с номерами 51, 6, 54, 55, 56 и одинаковыми полями имени, телефона и почты.
Перехват автоматически применяется и к новым формам Contact Form 7.

Нужны WordPress 5.8+, PHP 7.3+ и Contact Form 7 версии 5.4+ на сайтах с
формами. Поддерживается обычная установка и Multisite. Для всех сайтов
сети используйте **активацию для сети**. Плагин выбирает только основной
домен и его поддомены; другие домены этой сети остаются вне подключения.
Для отдельных установок WordPress на других серверах плагин устанавливается
на каждой из них; сетевой режим не получает доступ к чужим серверам.

1. Сделайте резервную копию WordPress через панель хостинга.
2. Исправьте существующий источник `lp.energo-365.ru` в Boykov Services
   командой из `correct-energo-source.sh` в архиве. На VPS Boykov Services
   она делает согласованную резервную копию базы и меняет домен на
   `energo-365.ru`, название — «Энерго 365». ID, ключ и заявки сохраняются.
   Если одновременно существуют два отдельных источника, скрипт останавливается
   с `BOTH_SOURCES_EXIST_NO_CHANGES`: потребуется проверить их перед объединением.
3. Используйте прежний URL и ключ исправленного источника. Если источник
   ещё не создавался, добавьте `energo-365.ru` со способом **Серверный агент**.
4. В админке сети WordPress → Плагины → Добавить новый → Загрузить плагин
   загрузите вложенный `boykov-leads-wordpress.zip`. Для обновления выберите
   замену текущего плагина загруженным. Затем **активируйте для сети**.
5. Откройте панель самого сайта `energo-365.ru` → Настройки → Boykov Services
   под администратором сети. Вставьте полный URL
   `https://boykov-services.ru/hooks/leads/…` и ключ **без** слова `Bearer`.
   Сохраните и проверьте. Ключ задаётся один раз для всей сети, не выводится
   обратно в HTML. Пустое поле сохраняет действующий ключ.
6. В этой странице проверьте список подключаемых доменов. В планировщике
   хостинга добавьте запуск каждую минуту (`* * * * *`), скопировав команду
   из настроек. Для основного сайта обычно используется:

   ```bash
   wget -q -O /dev/null --timeout=30 'https://energo-365.ru/wp-cron.php?doing_wp_cron'
   ```

   На Beget это делается через панель Cron: все минуты и все часы.

7. Без посещений публичных страниц убедитесь, что время подтверждённого
   отчёта продолжает обновляться. Отправьте контрольные заявки с основного
   сайта и каждого поддомена, из каждой используемой формы. Проверьте поле
   «Сайт» и совпадение контактов в Boykov Services.

В Multisite очереди хранятся отдельно в таблицах каждого сайта. Один
координатор собирает и отправляет их с общим ключом. Отчёт суммирует
ожидающие и отклонённые записи всех подходящих сайтов и выбирает самую
старую ожидающую заявку. Ошибка чтения одного поддомена делает общий
отчёт неисправным. Отдельные пустые очереди не перезаписывают этот отчёт
нулевыми показателями. Порядок обхода меняется между запусками.

Новые поддомены этой сети подхватываются автоматически. Если ранее
созданная очередь исчезла, плагин сообщает об ошибке, сохраняя необходимость
восстановления из резервной копии. Пустая таблица вместо утраченных данных
автоматически не создаётся.

## Сохранение и доставка

`wpcf7_before_send_mail` вызывается Contact Form 7 после проверки полей,
согласия и спама. До обычной отправки письма плагин сохраняет отдельную
строку-снимок с UUID и исходным временем. Если запись не подтверждена базой,
форма прерывается с сообщением о невозможности сохранить заявку.

Внешних HTTP-запросов в публичном обработчике нет. Почта и текущие CRM
дальше работают обычным способом. Ошибка отправки письма не удаляет уже
сохранённую копию. Сразу после активации сохраняются и заявки, пришедшие
до настройки ключа. Обращения до установки автоматически не импортируются:
сама Contact Form 7 их не хранит. Для импорта из Flamingo или другого
архива сначала нужно проверить фактическое хранилище.

Отправитель читает неизменяемые байты снимка, проверяет TLS и не следует
редиректам. Подтверждение — только HTTP 200/201 с JSON, `ok:true`,
совпадающими `siteId`, `eventId` и номером сохранённой записи центра.
При тайм-ауте или потере подтверждения повторяются те же UUID и содержимое.
Центр возвращает исходный номер, не создавая вторую заявку.

За запуск отправляется до 20 строк с ограничением общего времени работы.
От параллельных отправителей защищает сессионная блокировка MySQL;
потеря блокировки не позволяет записать неподтверждённую доставку.
Сеть, 401/403, 429 и 5xx оставляют заявки в очереди с повтором до 15 минут.
400/409/413/422 сохраняют оригинал в статусе «Требует разбора», который
виден в отчёте центра. После исправления причины можно отметить
«Повторить также отклонённые записи» и запустить отправку.

Адрес разрешён только на `https://boykov-services.ru/hooks/leads/…`.
После сохранения он привязан к очереди: заменить его адресом другого сайта
через настройки нельзя. Ротация ключа того же сайта разрешена.

Поля сохраняются целиком, включая массивы. CAPTCHA, служебные поля
и параметры авторизации исключаются. Слишком большие записи не обрезаются
для обхода ограничений центра: оригинал остаётся в очереди и требует
разбора. Текущие пять форм не содержат загрузки файлов; содержимое
вложений эта версия коннектора не переносит.

Отчёт содержит количество ожидающих и отклонённых записей и дату самой
старой ожидающей заявки. В сетевом режиме отчёт проверяет чтение очередей всех поддоменов. Отсутствие отчётов видно в центре и настройках
плагина. Проверка связи не подтверждает правильность каждой отдельной
формы — для этого нужны контрольные обращения.

## CLI-вариант расписания

При блокировке HTTP-запросов к `wp-cron.php` можно запускать каждую минуту:

```bash
/ACTUAL/PHP/CLI /ACTUAL/SITE/wp-content/plugins/boykov-leads/run.php /ACTUAL/SITE/wp-load.php >/dev/null 2>&1
```

Замените три пути фактическими. Нужен CLI PHP 7.3+. Этот запуск выполняет
только доставку коннектора, не требует WP-CLI, не содержит ключа в командной
строке и не меняет настройку `DISABLE_WP_CRON` работающего сайта.

## Обслуживание

Очередь — таблица `<prefix>boykov_lead_outbox`, ключ — настройка WordPress
с выключенной автозагрузкой; в Multisite используется общая настройка сети. Изменения и ручной запуск требуют WordPress nonce и права
`manage_options`, а в сетевом режиме — `manage_network_options`. Публичного API чтения очереди или ключа
плагин не создаёт. Доступ к самой базе и резервным копиям нужно защищать
обычным для сайта способом.

Снимки автоматически не удаляются. Резервируйте базу WordPress вместе
с таблицей и настройками. Деактивация останавливает сбор и доставку,
но деактивация и удаление плагина не стирают очередь и ключ. Повторная
установка на тот же сайт продолжает работу с прежними снимками.
На время отключения сверяйте обращения с существующей почтой/CRM.

## Проверки разработки

```bash
npm run check
```

PHP-проверки запускаются при наличии PHP 7.3+ (`PHP_BIN` задаёт путь).
Для тестов настоящей InnoDB-очереди, параллельных соединений и повтора
в работающий модуль центра нужна отдельная одноразовая локальная база:

```bash
PHP_BIN=/path/to/php \
WP_TEST_MYSQL_SOCKET=/path/to/local/mysql.sock \
WP_TEST_MYSQL_DATABASE=boykov_wp_test_queue \
node --test tests/leads-wordpress.test.js
```

Имя базы должно начинаться с `boykov_wp_test_`. Тесты пересоздают свою
таблицу только в этой базе. Не задавайте базу рабочего WordPress.
