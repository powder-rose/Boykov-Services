# Аккаунты и личный кабинет

На экране входа есть «Личный аккаунт» (логин и пароль) и «Общий вход»
(действующий пароль команды). Персональная сессия действует 12 часов.
Общий пароль и действующие общие сессии сохраняются при обновлении.
Все активные аккаунты используют существующие рабочие сервисы. Общая история
и общий список заявок доступны как раньше; личный кабинет показывает свою
работу и не заменяет общий список. Управление аккаунтами доступно только роли
«Администратор» и недоступно через общий вход или аккаунт продаж.

## Первичная настройка

В патче есть отдельный `sales-accounts.json` с подготовленными именами и логинами.
Он не применяется в исходники и не включается в Git. Отправьте его на свой VPS:

```powershell
scp (Join-Path $patchDir 'sales-accounts.json') root@194.58.103.78:/root/boykov-sales-accounts.json
```

После commit и push, на VPS Boykov Services:

```bash
umask 022
cd /opt/boykov-services
git pull --ff-only && bash scripts/deploy-accounts.sh /root/boykov-sales-accounts.json
```

Скрипт проверяет список, делает онлайн-снимок SQLite и сохраняет старый образ,
собирает только `app`, проверяет миграцию и защиту API, затем подготавливает
аккаунты продаж. Они выключены и не имеют паролей до настройки администратором.
Повторная подготовка списка не меняет ранее созданные аккаунты или пароли.
Сервис документов не перезапускается; текущая генерация продолжает работать.
Ожидаемый результат: `ACCOUNTS_DEPLOY=OK`, `SALES_ACCOUNTS_PREPARED=OK`, `BACKUP`.

Создайте отдельного первого администратора в интерактивной консоли:

```bash
docker compose exec app node server/manage-accounts.js init-admin
```

Логин по умолчанию — `admin`, имя — «Администратор». Пароль задаётся со скрытым
вводом и повторным подтверждением, от 12 до 128 символов. Запускайте команду
без `-T`: ей нужен терминал. Пароль не передаётся аргументом и не печатается.
Если активный администратор уже существует, команда не меняет его доступ.

Войдите на сайте через «Личный аккаунт» и откройте «Аккаунты». Для каждого
подготовленного сотрудника нажмите «Задать пароль», введите пароль дважды и
отметьте «Доступ включён». Здесь же можно создавать новые аккаунты, менять
имя/логин/роль, сбрасывать пароль и отключать доступ. Смена пароля, логина,
роли или состояния закрывает прежние персональные сессии. Имя можно изменить
без закрытия сессии. Последнего активного администратора нельзя отключить
или перевести в отдел продаж.

## Авторство заявок

«Взять в работу» закрепляет заявку за текущим аккаунтом и меняет статус.
В таблице рядом со статусом показываются инициалы и имя, в карточке —
ответственный, обработавший сотрудник и время завершения.

Обычный комментарий не меняет ответственного. Для явного переназначения есть
кнопка «Взять себе». Два одновременных изменения защищены проверкой версии.
При переводе в «Обработана» сохраняется обработавший аккаунт. Если ответственный
и обработавший сотрудник различаются, оба видны в карточке. Повторное
редактирование комментария не подменяет автора обработки.

Возврат в «Новую» снимает назначение, возврат из «Обработана» в «В работе»
закрепляет заявку за сотрудником, который возобновил работу. В истории остаются
все предыдущие действия и имена на момент изменения. Удаление и восстановление
из корзины тоже записывают автора и сохраняют ответственного. Вход через общий
пароль подписывает новые действия как «Общий доступ». Исторические записи без
автора не приписываются сотрудникам задним числом. Данные автора из тела запроса
не используются: сервер берёт аккаунт из сессии.

## Мой кабинет

У каждого аккаунта есть вкладки «Мои документы», «В работе у меня» и
«Обработанные мной», отдельные счётчики и страницы по 30 записей. Из кабинета
можно открыть карточку заявки, посмотреть документ или скачать готовый договор.
Обработанные заявки выбираются по аккаунту, который присвоил статус «Обработана».
В корзине записи не входят в личные списки и счётчики. После восстановления
они снова доступны соответствующему сотруднику.

Новые договоры связываются с автором до отправки задачи сервису документов.
Номер задачи совпадает с UUID запроса; резервирование владельца фиксируется
SQLite COMMIT до удалённого вызова. Потеря ответа или повтор запроса не меняют
автора и не создают второй договор. Другой аккаунт не может присвоить себе
существующий номер генерации. Ранее созданные документы, для которых автор не
хранился, остаются в общей истории. Личное авторство старым документам не
назначается. При недоступности сервиса документов кабинет показывает
предупреждение, а личные заявки продолжают работать.

## Хранение и откат

Учётные записи, хеши паролей scrypt, персональные сессии и привязки документов
хранятся в `platform.sqlite`. Общая таблица сессий сохраняет прежнюю схему,
персональные сессии находятся отдельно в `account_sessions`. Пароли и хеши
не возвращаются API; ключи приёмщиков сайтов не дают доступа к аккаунтам.

Миграция добавляет новые таблицы и поля авторства без удаления старых данных.
В каталоге BACKUP находится `rollback-app.sh`: он возвращает предыдущий образ,
не накатывая старую базу поверх поступивших заявок. При откате используется
общий вход; персональные аккаунты и кабинет появятся после возврата новой
версии. Настроенные аккаунты и привязки остаются в базе.
